# Ouro Agent 游戏性后续迭代计划

> 日期：2026-05-16
> 输入：`18_游戏性可玩性迭代规格_20260516.md`、2026-05-16 mock 试玩
> 目标：把“能跑、能看”的版本推进到“每局都有选择、每场都有反制、每次失败都想再开一局”。

---

## 1. 当前体感

已成立：

1. CLI 游戏化方向成立，左右对战画面、动作帧、英雄卡和战报可读。
2. Mock provider 可完整试玩，不依赖网络和 API key。
3. 6 英雄、装备、词条、羁绊和 Prompt 模板已经构成基本 Build 面。
4. 路线、奖励、商店、休息已出现，可以承载肉鸽层。

仍需打磨：

1. 选择页说明不足，玩家难以预判收益。
2. 奖励与 Build 的关系还不够“拿下去就爽”。
3. Boss 和防御型英雄容易拖成低输出循环。
4. 失败复盘没有足够指出下一局怎么改。
5. 批量平衡统计还偏战斗结果，缺少体验节奏指标。

---

## 2. 迭代路线

### P0. 可玩闭环强化

目标：让玩家每次路线/奖励/失败都能理解。

| 顺序 | 需求 | 交付 |
|------|------|------|
| 1 | REQ-PLAY-001 路线风险收益 | 路线卡展示风险、预期消耗、收益、Build 适配、侦察信息。 |
| 2 | REQ-PLAY-002 奖励前后变化 | 奖励卡展示属性、标签、Build 阶段和下一战策略影响。 |
| 3 | REQ-PLAY-004 失败归因 | 战报从 trace 归因，输出 1-3 条下一局建议。 |
| 4 | REQ-BAL-002 节奏指标 | batch 增加英雄回合分布、超时原因、MP 枯竭、输出不足、循环风险。 |

验收证据：

1. `ouro run --mock --seed 7 --no-animation --auto` 输出里能看到选择影响和失败建议。
2. `ouro batch --count 50 --seed 100 --quiet` 输出节奏指标。
3. 至少补 1 个失败 seed、1 个胜利 seed 的人工试玩记录。

### P1. 肉鸽选择增厚

目标：把商店、休息、Prompt 调整变成局内修正工具。

| 顺序 | 需求 | 交付 |
|------|------|------|
| 1 | REQ-PLAY-003 商店/休息修正 | 商店卖恢复、定向标签、Prompt 风格调整、侦察；休息三选一。 |
| 2 | REQ-PLAY-005 Prompt 阈值 | 模板影响收割、打断、防御、MP 保留阈值，并在 trace/战报显示。 |
| 3 | REQ-STORY-001 场景短叙事 | 给新手副本补首见预兆、节点句、Boss 句、图鉴碎片。 |

验收证据：

1. 同一 seed 下切换 Prompt 模板，行动统计发生可解释变化。
2. 商店或休息选择能改变下一战 HP/MP、标签或 Prompt 上下文。
3. 玩家能从 Boss 前提示推断“需要打断或爆发”。

### P2. 内容与图鉴驱动

目标：让怪物机制、图鉴和 Build 形成长期动力。

| 顺序 | 需求 | 交付 |
|------|------|------|
| 1 | REQ-MON-001 怪物家族三档 | 至少 4 家族 I/II 档，1 个 III 档 Boss；机制可反制。 |
| 2 | REQ-CODEX-001 图鉴注入 | 已观察/掌握信息进入 prompt，未解锁信息保留迷雾。 |
| 3 | REQ-CONTENT-004 英雄内容验收 | 6 英雄从“已存在”升级为“各有推荐路线、弱点、关键奖励”。 |

验收证据：

1. 图鉴卡从 locked -> observed -> mastered 可见变化。
2. 已掌握怪物的信息改变模型目标选择或技能选择。
3. 每名英雄有一条推荐新手路线和一条反例路线。

## 3. 推荐实现批次

### Batch G1：选择解释

范围：

1. 路线卡文案和字段。
2. 奖励卡前后对比。
3. 战报记录本局路线/奖励选择。

原因：投入小，立刻提升“我在玩”的感觉。

### Batch G2：失败复盘与节奏统计

范围：

1. 失败归因规则。
2. batch 节奏指标。
3. 超时与低输出循环检测。

原因：当前最明显的痛点是“差一点输”和“防御 Boss 超时”缺少解释。

### Batch G3：资源修正节点

范围：

1. 商店恢复/标签/侦察。
2. 休息三选一。
3. Prompt 风格中途调整。

原因：给玩家提供从失败教训到下一局改法的实际工具。

### Batch G4：怪物机制教学

范围：

1. 首见预兆。
2. 战中反制提示。
3. 战后图鉴碎片。

原因：让敌人从数值包变成可学习对象。

---

## 4. 平衡红线

1. 普通战不应超过 8 个英雄行动，除非有明确机制教学。
2. Boss 战不应因为防御循环超过 30 个英雄行动；超过则必须有破局机制或狂暴/处决规则。
3. 默认 mock 新手 run 不要求必胜，但失败必须显得合理且可改进。
4. 每个英雄至少有一个推荐新手策略能稳定打到 Boss。
5. 防御型 Build 可以慢，但必须有“防守转输出”的高潮窗口。
6. 输出型 Build 可以脆，但必须有可见的收割回报。

## 5. 试玩记录摘要

### 阿斯缇娅 seed 7

命令：

```bash
venv312/bin/ouro --lang zh run --mock --seed 7 --no-animation --auto --trace-dir /tmp/ouro_gameplay_plan_trace
```

结果：

1. 第 1 战胜利，第 2 战胜利，第 3 战失败。
2. 失败时敌人仅剩 3 HP，英雄 HP 归零。
3. 体感问题：奖励和休息没有足够让玩家预见“下一战会不会缺 MP/缺输出”。

### 诺恩 seed 7

命令：

```bash
venv312/bin/ouro --lang zh run --mock --seed 7 --no-animation --auto --hero hero_ash_guardian --trace-dir /tmp/ouro_gameplay_plan_trace_norn
```

结果：

1. 能推进到 Boss。
2. Boss 战 600 ticks 超时，48 次英雄行动里 24 次普攻、24 次塔盾防御。
3. 体感问题：防御循环安全但不够有趣，需要防守转输出、Boss 破防或超时前的明确破局提示。

---

## 6. 下一步建议

优先做 Batch G1 + G2。它们不需要大规模内容扩展，直接作用于当前已有路线、奖励、战报和 batch 工具，能最快把现有版本从“功能完整”推进到“选择可解释、失败可学习”。

# Ouro Agent 界面、美术、策划与数值实施计划

> 日期：2026-05-16
> 输入：`19_界面美术策划数值联合实施规格_20260516.md`
> 目标：拆分后续实现批次，让界面效果、模块排布、策划信息和数值节奏一起被验收。

---

## 1. 实施原则

1. 先统一布局，再增加内容。
2. 先修战斗主屏和选择页，再调复杂 Boss。
3. 每个 UI 模块都要有 80/100 宽度快照。
4. 每次数值调整都要配 batch 指标，不凭单局体感拍脑袋。
5. 不改变核心产品边界：单英雄、战斗中自动行动、模型只选 action、本地裁判结算。

---

## 2. 批次拆分

### Batch UI-0：视觉基线和快照框架

目标：先让“好看”和“正常排布”可验收。

任务：

1. 定义全局面板宽度、卡片 padding、标题、分隔线、短状态名。
2. 建立 80/100/120 宽度快照入口。
3. 为主菜单、英雄列表、英雄详情、路线、奖励、战斗、战报建立 golden 输出。
4. 增加 no-color / ascii-safe / unicode 三种模式检查。

对应需求：

1. REQ-UIQA-001
2. REQ-ART-003
3. REQ-QA-001

验收：

1. 80 列下无边框错位。
2. 中文输出不撑破面板。
3. `--no-animation` 仍保留完整 turn frame。

### Batch UI-1：战斗主屏重排

目标：让当前最核心的战斗画面达到优秀界面效果。

任务：

1. `ACTION` 上移到 Build/Session/Log 之前。
2. `NEXT PICK` 拆为 `NEXT` 和 `NEED` 两行，最多 top 2。
3. 状态主屏显示短名，完整 ID 写详情/trace。
4. 模型思考压缩为 2 行；长文本进入 trace。
5. 多敌人时右侧主面板显示当前目标，敌方队列短列表显示其他敌人。

对应需求：

1. REQ-BATTLEUI-001
2. REQ-UIQA-001

验收：

1. 阿斯缇娅 seed 7 第 3 战输出不挤压。
2. 100 列默认画面中，玩家先看到行动、目标、伤害、裁判。
3. 80 列压缩画面仍能看见 HP/MP/ATB、ACTION、LOG。

### Batch PLAY-1：路线与奖励选择升级

目标：让玩家的战斗外选择有清晰预期。

任务：

1. 路线卡增加风险、预期消耗、收益、Build 适配、侦察。
2. 奖励卡增加属性/标签/Build 阶段前后变化。
3. 战报记录本局关键路线和奖励选择。
4. 对不适配奖励标记 `cross-seed` 或 `future build`。

对应需求：

1. REQ-PLAY-001
2. REQ-PLAY-002

验收：

1. 玩家不用打开文档，也能知道为什么选战斗/商店/休息。
2. 选择奖励前能看出离 `[HIGH]` 或羁绊还差什么。

### Batch PLAY-2：商店、休息和失败复盘

目标：把失败教训转化为下一局工具。

任务：

1. 商店四类货架：Recover、Build、Prompt、Scout。
2. 休息三选一：Recover、Focus、Study。
3. 失败战报归因资源、目标、Build、路线。
4. 战报给 1-3 条下一局建议。

对应需求：

1. REQ-PLAY-003
2. REQ-PLAY-004

验收：

1. 阿斯缇娅 seed 7 失败后能指出 MP/续航/奖励选择问题。
2. 玩家能在下一局通过商店或休息执行建议。

### Batch BAL-1：节奏指标与数值预算

目标：让数值调整服务观战节奏。

任务：

1. batch 报告增加英雄行动数分布、超时原因、MP 枯竭、连续普攻、防御循环。
2. 为普通/精英/Boss 写入节奏预算。
3. 标记 `tempo_outlier`，输出对应 seed。
4. 先对诺恩 Boss 超时做定性验证，再决定调 Boss 还是调诺恩机制。

对应需求：

1. REQ-BAL-002
2. REQ-BAL-003

验收：

1. `ouro batch --count 50 --seed 100 --quiet` 能定位拖长原因。
2. 防御循环和低输出循环不再只表现为 timeout。

### Batch BOSS-1：Boss 专属界面与破局

目标：让 Boss 战有阶段、反制和高潮。

任务：

1. Boss 主屏显示 Phase/Charge/Break/Enrage。
2. 黑烛主祭增加可读蓄力和破防提示。
3. 防御 Build 触发反击/破防/处决窗口。
4. Boss 战报显示错过的反制窗口。

对应需求：

1. REQ-BOSSUI-001
2. REQ-BAL-003

验收：

1. 诺恩 seed 7 不再无解释地 600 ticks 超时。
2. 即使失败，玩家也能知道错过了哪个窗口。

## 4. 人工验收清单

每个批次交付后至少做 3 次人工试玩：

1. 阿斯缇娅 seed 7：验证 MP/奖励/失败建议。
2. 诺恩 seed 7：验证防御循环和 Boss 破局。
3. 任一高速/输出英雄 seed 7 或 seed 100：验证输出型 Build 的收割高潮。

记录格式：

```text
Playtest
command:
result:
best moment:
confusing moment:
layout issue:
balance issue:
next action:
```

---

## 5. 完成定义

本计划完成时应满足：

1. 所有核心模块 80/100 宽度排布正常。
2. 战斗主屏第一眼能看懂当前行动和结算。
3. 路线与奖励选择能看出风险收益和 Build 后果。
4. 商店/休息能修正局内问题。
5. 失败战报能指导下一局。
6. batch 报告能发现拖长、普攻化、防御循环和 MP 枯竭。
7. Boss 战有阶段、反制窗口和专属界面。

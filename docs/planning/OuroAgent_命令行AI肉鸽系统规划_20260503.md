# Ouro Agent 命令行 AI 肉鸽系统规划

> 日期：2026-05-03  
> 暂定名：Ouro Agent: Prompt Legend  
> 状态：规划草案，等待 MVP 范围审批

---

## 1. 一句话定位

Ouro Agent 是一个严肃暗黑风格的命令行 AI 肉鸽游戏：玩家构筑一个英雄 Agent，配置角色、装备、技能、词条、Build 和 Prompt；战斗开始后玩家不能操作，由模型在 BattleLLMSession 中按读条窗口自动决策，玩家通过命令行观战和在关卡之间运营。

核心优先级：

1. 先做一个好玩的单机 CLI 肉鸽。
2. AI 是战斗决策核心，但结算必须由本地规则引擎裁判。
3. Prompt、装备、技能、词条不是装饰，而是共同组成英雄的行为系统。
4. 后续可扩展无限模式排行榜和玩家模型对战。

---

## 2. 核心循环

```text
选择英雄
  ↓
配置初始 Build / 装备 / 技能 / 英雄 Prompt
  ↓
进入副本地图
  ↓
玩家选择路线节点
  ↓
战斗节点：AI 自动战斗，玩家观战
非战斗节点：商店、装备替换、Prompt 调整
  ↓
结算金币、经验、装备、Build、图鉴进度
  ↓
继续选路
  ↓
Boss / 通关 / 死亡 / 无限推进
```

玩家的主要操作点在战斗外：

| 操作点 | 玩家做什么 |
|--------|------------|
| 开局 | 选择英雄、初始装备、技能、Build、Prompt |
| 选关 | 在分叉路线中选择普通怪、宝箱怪、商店、Boss 等节点 |
| 关卡之间 | 购买装备、替换 Build、调整英雄 Prompt |
| 战斗中 | 不能操作，只能观看 AI 行动反馈 |

## 3. 战斗模型

战斗采用读条制。早期实现可以在每次英雄行动条满时发起一次模型请求；下一阶段升级为方案 A2：**每场战斗创建一个 BattleLLMSession，英雄行动条满时向同一 Session 发送 turn delta 并获取 action**。

```text
读条推进
  ↓
单位行动条满
  ↓
如果是英雄行动：向 BattleLLMSession 发送 turn delta
  ↓
模型读取本回合 delta、Build 摘要、已解锁图鉴、冷却、法力
  ↓
模型输出自然语言反馈 + 结构化行动
  ↓
裁判校验行动合法性
  ↓
本地引擎结算伤害、状态、冷却、法力
  ↓
CLI 播放动作、伤害、状态、读条变化
```

敌人可以先由规则或简单 AI 控制，MVP 阶段不需要每个敌人也调用模型。

---

## 4. 模型行动协议

模型每次行动必须输出两层内容：

| 层 | 用途 | 是否参与结算 |
|----|------|--------------|
| 自然语言反馈 | 给玩家看角色在做什么、为什么这么做 | 否 |
| 结构化 action | 给游戏引擎校验和结算 | 是 |

建议第一版 schema：

```json
{
  "narration": "艾拉后退半步，抬手释放暗影尖刺，优先压低后排咒术师的血线。",
  "analysis": "咒术师读条接近完成，且图鉴显示它会释放群体伤害。",
  "action": {
    "type": "cast_skill",
    "skill_id": "skill_shadow_sting",
    "targets": ["enemy_02"],
    "modifier": "focus_fire"
  },
  "confidence": 0.78
}
```

裁判只认 `action`。`narration` 和 `analysis` 只用于展示、战报和后续调试。

可选通用动作：

| 动作 | 说明 |
|------|------|
| `basic_attack` | 普通攻击，不消耗法力，通常无冷却 |
| `cast_skill` | 使用技能，受法力值和冷却限制 |
| `use_item` | 使用道具，受库存限制 |
| `defend` | 防御或架势调整 |
| `observe` | 观察敌人，可能推进图鉴或获得临时情报 |
| `change_stance` | 调整战斗姿态，影响后续偏好或属性 |

## 5. 法力与冷却

英雄有法力值，技能有冷却。模型在决策前必须看到当前资源和冷却状态：

```text
可用技能：
- 暗影尖刺：消耗 12 MP，冷却 0，可用
- 腐蚀新星：消耗 25 MP，冷却 2，不可用
- 深渊屏障：消耗 18 MP，冷却 0，可用
```

模型如果选择不可用技能，进入降级/惩罚流程。

## 6. 格式错误与非法行动处理

模型能力会影响游戏表现，但不能让玩家因为一次格式波动直接失去体验。建议三档处理：

| 情况 | 处理 | 游戏后果 |
|------|------|----------|
| JSON 可修复 | 自动修复，记录瑕疵 | 行动正常 |
| JSON 不合法但可读出意图 | 降级解析 | 行动效果降低，例如伤害 -20% |
| 完全不可用 / 虚构技能 / 资源不足 | 裁判拒绝 | 改为普通攻击、犹豫跳过或读条损失 |

这套机制同时服务游戏性和后续模型表现记录。

## 7. Session 管理

方案 A2 要避免每回合重复输入完整上下文，因此必须设计 session 分层。

| Session | 生命周期 | 保存内容 |
|---------|----------|----------|
| Run Session | 一整局肉鸽 | 英雄、金币、经验、装备、路线、图鉴进度、遗物 |
| Dungeon Session | 一个副本 | 地图路线、节点状态、Boss 机制、临时增益 |
| Battle Session | 一场战斗 | 敌我状态、行动历史、错误次数、战斗日志 |
| Battle LLM Session | 一场战斗内持续存在的模型会话 | static context、turn delta、rolling summary、session trace |
| Model Turn Session | Battle LLM Session 内的一次模型行动 | turn delta、原始输出、解析结果、裁判结果 |

Battle LLM Session 初始化时注入静态上下文：

| Static 区块 | 内容 |
|-------------|------|
| System Rules | 游戏规则、禁止虚构、必须输出结构 |
| Hero Identity | 英雄职业、性格、默认打法 |
| Build Context | 装备、技能、词条、羁绊、Build 类型 |
| Enemy Intel | 已解锁图鉴信息 |
| Player Strategy | 玩家配置的英雄 Prompt |
| Output Schema | 必须遵守的 JSON 格式 |

每次模型行动只追加 turn delta：

| Delta 区块 | 内容 |
|------------|------|
| Battle State | HP、MP、状态、读条、冷却、敌我位置 |
| Recent Turns | 最近 3-6 次关键行动摘要 |
| Judge Result | 上一次本地裁判结果 |
| New Intel | 本场新观察到但允许展示的信息 |

## 8. 关卡节点

| 节点 | 是否战斗 | 收益 | 设计价值 |
|------|----------|------|----------|
| 普通怪 | 是 | 金币 + 经验 | 基础成长 |
| 精英怪 | 是 | 更多经验 + 稀有掉落 | 风险收益 |
| 宝箱怪 | 是 | 金币 + 经验 + 装备/Build 选择 | 构筑刺激 |
| 商店 | 否 | 购买、替换、调整 Prompt | 安全运营，但少拿经验 |
| 事件 | 可选 | 增益、诅咒、交易 | 肉鸽变化 |
| Boss | 是 | 通关、解锁、大额奖励 | 阶段检验 |

商店节点不战斗，玩家可以购买装备、替换 Build、调整英雄 Prompt，但会失去通过战斗获得经验和掉落的机会。

## 9. 装备、词条、Build 档次

装备、词条、Build 分三档：

| 档次 | 机制 | 示例 |
|------|------|------|
| 普通 | 偏数值；模型正确使用即可生效 | 长剑：普通攻击 +8 |
| 英雄 | 数值更高 + 固定触发效果 | 处刑者：攻击低于 30% HP 的敌人时追加伤害 |
| 传奇 | 数值更高 + 有限自由度；模型可根据敌人差异选择不同使用方式 | 黑日法典：引用图鉴弱点后触发不同暗影效果 |

传奇装备不能允许模型随意编效果，应该给它有限选项：

```yaml
name: 黑日法典
tier: legendary
effect:
  base: 暗影技能伤害 +18%
  adaptive:
    rule: 模型可从 enemy_intel 中选择一个已知弱点触发额外效果
    allowed_effects:
      - brittle: 降低防御
      - silence: 延迟施法读条
      - fear: 降低下一次攻击
    judge: 必须引用图鉴或当前战况中的证据
```

## 10. 羁绊系统

羁绊是游戏好玩的关键。建议命名为 **回响 / Resonance**。

羁绊来源：

| 来源 | 示例标签 |
|------|----------|
| 装备 | 暗影、毒、流血、护盾、处刑 |
| 技能 | 单体、群体、持续伤害、打断 |
| 词条 | 腐化、冷静、贪婪、献祭 |
| 角色 | 术士、猎手、守卫 |
| Prompt | 控场、激进、保守、优先后排 |

Prompt 可以参与羁绊，但必须由系统解析成有限标签，不能玩家写“我有某某羁绊”就直接生效。

示例：

```text
羁绊：腐化学派 3/3
条件：装备、技能、词条、Prompt 标签中累计 3 个“腐化”
效果：
- 毒伤害 +20%
- 每当敌人中毒，英雄获得 3 点护盾
- 模型若选择扩散毒素，额外获得一次小幅读条推进
```

## 11. 图鉴系统

敌人信息通过图鉴逐步解锁，并存入英雄可引用的上下文目录。玩家 Prompt 可以影响英雄是否在战斗前研究图鉴。

| 阶段 | 解锁条件 | 模型可见信息 |
|------|----------|--------------|
| 未知 | 首次遭遇 | 名称、外观、基础 HP |
| 观察 | 遭遇 1 次 | 常见技能、伤害类型 |
| 熟悉 | 击败 2 次 | 抗性、弱点、读条速度 |
| 掌握 | 击败 5 次 | 完整机制、隐藏行为、推荐打法 |
| 猎杀 | 击败 10 次 | 特殊处决或克制策略 |

战斗前可以出现：

```text
[战前准备]
1. 快速进入战斗
2. 让英雄研究图鉴
3. 调整英雄 Prompt
```

如果英雄 Prompt 中写了“遇到未知敌人优先研究图鉴”，系统应在行动上下文里强化这一倾向。

## 12. 失败机制选项

可以参考成熟节点型肉鸽，给失败设计几种方向：

| 方案 | 失败后 | 优点 | 缺点 |
|------|--------|------|------|
| 传统肉鸽 | 本局结束，回主菜单 | 紧张感强，最纯粹 | 挫败感高 |
| 篝火续命 | 回到前一个安全节点，损失部分金币/装备 | 适合长局 | 惩罚较弱 |
| 污染复活 | 原地复活，但获得诅咒词条或 Prompt 污染 | 暗黑感强，适合 AI 主题 | 设计复杂 |
| 永久成长 | 本局结束，保留图鉴、成就、少量货币 | 长期驱动力强 | 可能变刷子游戏 |

推荐组合：**传统肉鸽 + 永久图鉴成长 + 少量污染复活**。

死亡默认结束本局，但保留图鉴进度、已发现装备、成就和少量残响货币。特殊传奇词条或事件可以触发污染复活：

```text
你在死亡边缘听见深渊回声。
是否接受污染复活？

获得：
- HP 恢复至 40%
- 本场战斗继续

代价：
- 新增诅咒 Prompt：你会更倾向于优先攻击血量最低的目标，即使它不是最高威胁。
```

## 13. MVP 建议范围

| 模块 | MVP 范围 |
|------|----------|
| 模式 | 新手副本 1 个 |
| 英雄 | 当前 3 个已实现，下一阶段规划 6 个：暗影学徒、灰烬守卫、裂弦猎手、瘟沼先知、坟场工匠、失声唱诗者 |
| 战斗 | 读条制；每场战斗一个 BattleLLMSession，英雄行动发送 turn delta；敌人规则控制 |
| 资源 | HP、MP、技能冷却、状态效果 |
| 节点 | 普通怪、宝箱怪、商店、Boss |
| 装备 | 普通、英雄、传奇三档各少量 |
| 羁绊 | 先做 3-5 个固定羁绊 |
| Prompt | 开局可配置，商店可大改，战后可小改 |
| 图鉴 | 敌人信息按怪物家族 + 三档分阶段解锁 |
| 输出 | CLI 动画、血条、读条、行动日志、关卡结算 |

暂缓：

1. 小队系统。
2. 多人对战。
3. 在线排行榜。
4. 复杂剧情。
5. 敌方也调用模型。

## 14. 后续扩展

| 方向 | 说明 |
|------|------|
| 无限模式 | 适合后续排行榜，记录层数、耗时、成本、胜率 |
| 玩家模型对战 | 玩家选择自己的模型和构筑，异步或同步对战 |
| 模型表现档案 | 记录合法率、冷却误用、资源管理、战术稳定性 |
| 自定义副本 | 玩家分享敌人、词条、规则集 |
| Build 分享码 | 方便分享英雄构筑和 Prompt |

## 15. 当前未决问题

1. 第一版 CLI 技术栈：Python、Node.js 还是 Rust。
2. 模型接入方式：OpenAI-compatible API、单一 provider，还是多 provider adapter。
3. 战斗动画尺度：逐字日志、轻量 TUI，还是更完整的 curses/Ink 风格界面。
4. 首批英雄的具体技能与默认 Prompt。
5. 失败后永久成长的货币和解锁边界。
6. 模型调用成本控制：是否提供低成本模式或本地模型模式。

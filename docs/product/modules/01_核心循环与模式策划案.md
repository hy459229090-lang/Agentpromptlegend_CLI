# G01 核心循环与模式策划案

> 状态：v0.1 草案  
> 依赖：`02_设计基线与术语表_20260503.md`

---

## 1. 模块目标

定义玩家一局游戏从开始到结束的完整路径，确保 Ouro Agent 是“战斗外运营 + 战斗中观战”的肉鸽，而不是普通回合制 RPG。

---

## 2. 核心循环

```text
主菜单
  ↓
选择模式
  ↓
选择英雄
  ↓
配置初始 Build / Prompt
  ↓
进入副本地图
  ↓
玩家选择路线节点
  ↓
节点执行：战斗 / 商店 / 事件 / Boss
  ↓
结算奖励或失败
  ↓
继续路线，直到 Boss、死亡或通关
```

### 2.1 可感知体验循环

实现时不能只完成状态流转，必须让玩家在屏幕上看到每个阶段的反馈：

```text
入口状态可见
  ↓  provider / model / mock / language / visual mode
英雄与 Build 可见
  ↓  武器、技能、标签、羁绊、Prompt 倾向
副本选择可见
  ↓  路线风险、收益、节点类型
战斗过程可见
  ↓  每个 turn 的动作帧、伤害、状态、日志
结算原因可见
  ↓  胜负、关键伤害、技能使用、图鉴/奖励
下一步选择可见
  ↓  奖励、商店、休息、Prompt 调整
```

不通过条件：

1. 战斗只在结束后显示最终画面。
2. 路线、奖励、商店在玩家试玩模式下静默自动选择。
3. 玩家只能从 trace 才能知道发生了什么。
4. 只有接口字段和 action id，没有角色动作与数值变化反馈。

---

## 3. 玩家控制边界

| 阶段 | 玩家能做什么 | 玩家不能做什么 |
|------|--------------|----------------|
| 开局 | 选英雄、选初始配置、写 Prompt | 修改底层规则 |
| 路线选择 | 在可见节点中选择下一关 | 直接跳关或指定掉落 |
| 商店 | 买卖、替换装备、调整 Prompt | 获得战斗经验 |
| 战斗中 | 观看、暂停、加速、查看日志 | 手动选择技能或目标 |
| 战后 | 选择奖励、查看战报 | 改写战斗结果 |

### 3.1 自动与半自动

| 模式 | 玩家控制 | 使用场景 | 要求 |
|------|----------|----------|------|
| 自动观战 | 战斗中只控制观看节奏 | 默认战斗体验 | 逐 turn 显示动作帧和日志 |
| 半自动策略 | 战斗外选择 Prompt 模板、策略槽、Build 倾向 | 默认副本体验 | 战斗内仍由模型选 action |
| 全自动批跑 | 路线/奖励/战斗均自动 | 数值测试、CI | 必须标记为 batch/auto，不作为玩家试玩默认 |
| 手动调试 | 指定 seed、敌人、Provider、no-animation | 开发验证 | 输出必须可复现 |

半自动策略是 MVP 最适合的可玩形态：玩家在战斗外表达倾向，战斗内观看 Agent 执行。

---

## 4. 模式设计

| 模式 | MVP | 说明 |
|------|-----|------|
| 新手关 | 必做 | 教会玩家选路、观战、奖励、Prompt 调整 |
| 普通副本 | 可延后 | 多个难度副本 |
| 无限模式 | 延后 | 排行榜基础 |
| 模型对战 | 延后 | 玩家配置模型和 Build 对战 |

MVP 只要求新手关完整。

---

## 5. 新手关结构

建议第一版固定 5 层：

| 层 | 节点选择 |
|----|----------|
| 1 | 普通怪 |
| 2 | 普通怪 / 商店 |
| 3 | 宝箱怪 / 精英怪 |
| 4 | 商店 / 事件 |
| 5 | Boss |

目标：让玩家在 10 分钟内完成或失败一局。

---

## 6. 验收标准

1. 玩家能从主菜单进入一局。
2. 玩家能完成至少一次路线选择。
3. 战斗开始后玩家不能手动控制英雄行动。
4. 通关、死亡、退出都有明确状态。
5. 新手关能用 mock model 完整跑通。
6. 新手关默认试玩模式下，玩家能看到每场战斗的实时动作帧和滚动日志。
7. 每场战斗结束必须展示可解释战报，而不只是 `victory/defeat`。

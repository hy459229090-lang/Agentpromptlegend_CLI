# G05 模型行动与 Prompt 策划案

> 状态：v0.1 草案  
> 依赖：设计基线、G02 战斗系统

---

## 1. 模块目标

让模型成为英雄战斗决策核心，同时保证游戏可控、可结算、可降级。

---

## 2. 模型输入

每次英雄读条满时，系统组合一次行动 Prompt。

必须包含：

1. 游戏规则摘要。
2. 英雄身份和默认倾向。
3. 当前 Build：装备、技能、词条、羁绊。
4. 当前战况：HP、MP、ATB、冷却、状态、敌人。
5. 已解锁图鉴信息。
6. 最近 3-6 次关键行动。
7. 玩家英雄 Prompt。
8. 输出 schema。

不能包含：

1. 未解锁图鉴。
2. 不存在的技能或道具。
3. 让模型决定伤害、掉落、胜负的指令。

---

## 3. 模型输出

建议 schema：

```json
{
  "narration": "给玩家看的动作描述",
  "analysis": "简短战术理由，只能引用已知信息",
  "action": {
    "type": "cast_skill",
    "skill_id": "skill_shadow_sting",
    "targets": ["enemy_hungry_cultist_02"],
    "modifier": "focus_fire"
  },
  "confidence": 0.78
}
```

只有 `action` 参与结算。`narration` 和 `analysis` 只用于展示和 trace。

---

## 4. Prompt 调整

玩家可以在以下时机调整英雄 Prompt：

| 时机 | 调整幅度 |
|------|----------|
| 开局 | 完整编辑 |
| 商店 | 完整编辑 |
| 战后 | 小幅调整，替换或追加一条策略 |
| 战斗中 | 不允许 |

后续可用经验提升 Prompt 容量或策略槽数量。

---

## 5. 降级与惩罚

| 情况 | 处理 | 展示 |
|------|------|------|
| JSON 可修复 | 修复后执行 | 记录“思绪短暂扭曲” |
| 意图可读但结构错误 | 降级执行，效果降低 | 展示动作不稳定 |
| 使用不可用技能 | 拒绝，改为普通攻击或犹豫 | 展示法力/冷却不足 |
| 虚构技能或目标 | 拒绝，记录严重错误 | 展示英雄迟疑 |
| 完全不可读 | 跳过或普通攻击 | 展示意志断线 |

惩罚要让玩家理解，但不能频繁毁掉体验。

---

## 6. Mock Model

MVP 必须先有 mock model：

1. 不调用真实 API。
2. 根据战况选择合法行动。
3. 能模拟格式错误样例。
4. 能跑完整战斗。

真实模型接入必须在 mock model 跑通后再做。

---

## 7. 验收标准

1. 每次英雄行动都走 action schema。
2. 非法 action 会被校验。
3. 模型自然语言不会影响结算。
4. Prompt 会进入行动上下文。
5. mock model 可跑完整新手战斗。

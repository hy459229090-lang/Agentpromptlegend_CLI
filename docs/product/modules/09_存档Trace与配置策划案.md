# G09 存档、Trace 与配置策划案

> 状态：v0.1 草案  
> 依赖：G01、G02、G05、G07、G08  
> 目的：保证 Ouro Agent 可复盘、可调试、可长期游玩，同时避免保存敏感信息。

---

## 1. 模块目标

存档、trace 与配置系统解决三件事：

1. 玩家进度能保留。
2. 战斗和模型行动能复盘。
3. API key、Prompt、模型响应等敏感数据有边界。

---

## 2. 存档范围

| 数据 | 是否保存 | 说明 |
|------|----------|------|
| 图鉴进度 | 保存 | 长期成长核心 |
| 已发现装备 | 保存 | 用于收藏和后续解锁 |
| 成就 / 通关记录 | 保存 | 长期目标 |
| 残响货币 | 保存 | 后续 meta 资源 |
| 当前 Run 状态 | MVP 可选 | 用于中断恢复 |
| 本局金币 | 仅 Run 内保存 | 死亡后清空 |
| 本局装备 | 仅 Run 内保存 | 死亡后清空 |
| API key | 不保存明文 | 只从环境变量或本地安全配置读取 |
| 原始模型响应 | 默认本地 trace | 不上传 |

---

## 3. Trace 范围

每场战斗建议记录：

1. Run ID。
2. seed。
3. 英雄 Build 摘要。
4. 敌人列表。
5. 每个 tick 的关键状态，MVP 可只记行动级别。
6. 每次 Model Turn 的输入摘要。
7. 模型原始输出。
8. 解析结果。
9. 裁判结果。
10. 降级或惩罚原因。
11. 战斗结论。

---

## 4. Trace 隐私等级

| 等级 | 内容 | 用途 |
|------|------|------|
| L0 | 本地完整 trace | 调试、个人复盘 |
| L1 | 脱敏战斗摘要 | 分享战报 |
| L2 | 指标统计 | 后续排行榜或模型评测 |

MVP 默认只做 L0 本地保存，不上传任何内容。

---

## 5. 配置项

玩家配置建议包括：

| 配置 | 说明 |
|------|------|
| provider | `mock` 或 OpenAI-compatible provider |
| model | 模型名 |
| api_base | API 地址，可选 |
| api_key_env | API key 环境变量名 |
| speed | 战斗播放速度 |
| animation | 是否开启动画 |
| trace_level | trace 记录级别 |
| seed | 固定 seed，便于复测 |

API key 不应写入普通配置文件。配置文件可以保存环境变量名，例如 `OPENAI_API_KEY`。

---

## 6. 可复测要求

为了后续调试，必须支持：

1. 固定 seed。
2. mock model。
3. 读取同一内容数据。
4. 保存 action trace。
5. 从 trace 中定位某次非法行动。

MVP 不要求完整 replay，但要保留未来实现 replay 的字段。

---

## 7. 不可做

1. 不默认上传 trace。
2. 不明文保存 API key。
3. 不把完整玩家 Prompt 自动发送到任何排行榜。
4. 不把 trace 设计成只适合真实模型，mock model 也要可记录。

---

## 8. 验收标准

1. 无 API key 也能进入 mock mode。
2. 一场战斗结束后能生成本地 trace。
3. trace 能看出模型输入、输出、解析、裁判和结算。
4. 死亡后图鉴进度能保留。
5. 配置错误有清晰提示，不导致程序崩溃。

# G12 玩家模型对战策划案

> 状态：v0.1 延后策划  
> 依赖：MVP、无限模式、稳定模型行动协议  
> 目的：先定义远期边界，避免早期战斗系统阻断未来 PvP / 模型对战。

---

## 1. 模块定位

玩家模型对战不是第一阶段目标。它的核心价值是：玩家配置英雄 Build、Prompt 和模型，让两个英雄 Agent 在同一规则下自动对战。

---

## 2. 对战形态

后续可选三种形态：

| 形态 | 说明 | 优先级 |
|------|------|--------|
| 异步镜像战 | 上传 Build 摘要，对方本地重放或挑战 | 高 |
| 同步观战 | 两边模型实时行动 | 中 |
| 官方挑战池 | 官方准备敌对 Agent，玩家挑战 | 高 |

第一版更适合做“官方挑战池”，比玩家实时对战更容易控制体验。

---

## 3. 对战公平性

需要控制：

1. 同一规则版本。
2. 同一内容版本。
3. 同一资源预算。
4. 同一英雄等级或构筑点数。
5. 模型调用超时规则一致。
6. 非法行动惩罚一致。

---

## 4. 对战数据

每个参战方需要：

1. 英雄 ID。
2. 装备和词条 ID。
3. 技能配置。
4. Prompt 摘要或可分享版本。
5. 模型名。
6. 规则版本。

不应上传完整私密 Prompt，除非玩家明确选择分享 Build。

---

## 5. 对战风险

| 风险 | 说明 |
|------|------|
| 成本高 | 双方都调用模型，消耗翻倍 |
| 等待慢 | 方案 A 每次行动调用模型，实时对战可能很慢 |
| 不公平 | 模型能力差异会压过构筑 |
| Prompt 注入 | 玩家 Prompt 可能试图影响对方或裁判 |
| 观战混乱 | 双方都输出自然语言，日志可能过载 |

---

## 6. MVP 需要预留什么

MVP 不做对战，但需要预留：

1. 英雄 Build 可序列化。
2. action schema 稳定。
3. 裁判不信任模型文本。
4. trace 可区分 actor 来源。
5. 模型调用有超时和失败处理。

---

## 7. 不可做

1. 不在单人玩法稳定前做玩家对战。
2. 不允许模型文本影响对方 Prompt。
3. 不把模型对战结果直接当模型总能力排行。
4. 不让玩家上传未脱敏私密 Prompt 作为默认行为。

---

## 8. 验收标准

进入该模块实现前必须满足：

1. 单机战斗协议稳定。
2. Build 可导出和导入。
3. 模型行动 trace 稳定。
4. 有规则版本和内容版本。
5. 有 Prompt 分享和隐私边界。

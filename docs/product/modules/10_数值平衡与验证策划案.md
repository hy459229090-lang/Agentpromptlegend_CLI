# G10 数值平衡与验证策划案

> 状态：v0.1 草案  
> 依赖：G02、G03、G04、G05、G08  
> 目的：让 MVP 可玩、可调，不在早期陷入无限平衡。

---

## 1. 模块目标

数值平衡第一阶段只服务 MVP 可玩性，不追求竞技公平。目标是让玩家能感知构筑变化、AI 决策质量和路线风险。

---

## 2. 第一版平衡原则

1. 新手副本目标时长 6-10 分钟。
2. 单场普通战斗目标 4-8 次英雄行动。
3. Boss 战目标 8-14 次英雄行动。
4. 普通怪失败率低，精英怪和 Boss 有明显风险。
5. 装备升级要明显，但不能让普通数值装备压过 Prompt 和羁绊。
6. 传奇装备提供选择空间，但必须可裁判。

---

## 3. MVP 建议数值范围

| 项 | 建议范围 |
|----|----------|
| 英雄 HP | 90-120 |
| 英雄 MP | 40-60 |
| 普通敌人 HP | 35-70 |
| Boss HP | 160-240 |
| 普通攻击伤害 | 8-14 |
| 低消耗技能伤害 | 18-30 |
| 高消耗技能伤害 | 30-50 |
| 普通技能 MP 消耗 | 8-18 |
| 高消耗技能 MP 消耗 | 20-35 |
| 技能冷却 | 1-4 次英雄行动 |

这些是起点，不是最终平衡。

---

## 4. 节点收益基线

| 节点 | 金币 | 经验 | 奖励 |
|------|------|------|------|
| 普通怪 | 10-20 | 8-15 | 低概率装备或词条 |
| 精英怪 | 20-35 | 16-28 | 高概率英雄档奖励 |
| 宝箱怪 | 15-30 | 10-20 | 三选一奖励 |
| 商店 | 无 | 无 | 购买和 Prompt 调整 |
| Boss | 40+ | 35+ | 通关奖励和解锁 |

---

## 5. 需要观察的指标

| 指标 | 用途 |
|------|------|
| 通关率 | 判断整体难度 |
| 单场战斗行动数 | 判断节奏是否拖 |
| AI 非法行动率 | 判断 Prompt 和 schema 是否清楚 |
| MP 不足失败次数 | 判断资源提示是否足够 |
| 冷却误用次数 | 判断模型上下文是否明确 |
| 玩家选择商店率 | 判断商店价值 |
| 羁绊触发次数 | 判断构筑是否有存在感 |
| 死亡节点分布 | 判断难度曲线 |

---

## 6. 验证方式

| 验证 | 要求 |
|------|------|
| mock model 自动跑 | 至少 20 局固定 seed 或 seed 集合 |
| 人工试玩 | 至少 3 局，记录体验问题 |
| 真实模型试玩 | 接 API 后再做，至少 3 局 |
| 非法输出测试 | 构造 JSON 错误、冷却错误、目标错误 |
| 内容校验 | 每次新增内容都跑 schema 校验 |

---

## 7. 不可做

1. 不在没有可玩闭环前做细平衡。
2. 不把高通关率直接等同于好玩。
3. 不让模型错误全由数值惩罚解决，优先改 Prompt 和 schema。
4. 不在 MVP 做复杂暴击、闪避、命中体系。

---

## 8. 验收标准

1. mock model 能完成 20 局批量试跑。
2. 能输出基础统计。
3. 新手副本失败原因可解释。
4. 至少 1 个羁绊在正常路线中能触发。
5. 商店路线和战斗路线都有选择价值。

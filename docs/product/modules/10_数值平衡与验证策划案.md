# G10 数值平衡与验证策划案

> 状态：v0.2 草案
> 依赖：G02、G03、G04、G05、G07、G08
> 目的：让 MVP 可玩、可调，并支撑英雄、怪物三档、Build 和图鉴扩展。

---

## 1. 模块目标

数值平衡第一阶段只服务可玩性，不追求竞技公平。目标是让玩家能感知：

1. 英雄差异。
2. Build 选择。
3. 怪物档次风险。
4. 图鉴解锁带来的策略优势。
5. 模型 Session 连续决策质量。

---

## 2. 第一版平衡原则

1. 新手副本目标时长 8-12 分钟。
2. 单场普通战斗目标 4-8 次英雄行动。
3. 精英战目标 6-10 次英雄行动。
4. Boss 战目标 8-14 次英雄行动。
5. 普通怪失败率低，II/III 档怪物必须有明显风险。
6. 装备升级要明显，但不能让普通数值装备压过 Prompt 和羁绊。
7. 传奇装备提供选择空间，但必须可裁判。

### 3.1 MVP 英雄第一轮推荐值

范围只能作为设计护栏，进入实现时必须给具体推荐值，并用固定 seed 验证。

| 英雄 | 定位 | HP | MP | SPD | ATK | DEF | POW | 普攻预期 | 关键风险 | 第一轮调整 |
|------|------|----|----|-----|-----|-----|-----|----------|----------|------------|
| Astia | 法术控制 | 100 | 72 | 12 | 8 | 6 | 16 | 4-5 | 技能使用率低 | 先改 Prompt 提醒，不急调数值 |
| Norn | 重甲守卫 | 140 | 32 | 8 | 12 | 13 | 6 | 6 | 输出不足但容错高 | 保持，观察战斗时长 |
| Vela | 高速猎手 | 90 | 36 | 16 | 14 | 4 | 10 | 7 | HP 过低导致真实模型容错差 | HP 80 -> 90 |
| Mirel | 毒沼消耗 | 100 | 72 | 10 | 9 | 6 | 18 | 4-5 | ATK 6 时普攻无意义 | ATK 6 -> 9，技能/毒伤优先 |
| Korr | 装置代理 | 110 | 42 | 9 | 14 | 8 | 16 | 7 | ATK 21 时技能多余 | ATK 21 -> 14，Gear 技能保留爆发 |
| Sera | 回声支援 | 105 | 68 | 11 | 8 | 6 | 16 | 4 | 依赖技能节奏 | 保持，观察技能循环 |

普攻预期按当前 `ATK / 2` 公式估算。若公式变更，本表必须同步更新。

### 3.2 英雄体验红线

| 红线 | 触发信号 | 优先处理 |
|------|----------|----------|
| 法系/毒系陷入无意义普攻 | basic_attack 连续 5 次以上且有 ready skill | Prompt tactical reminder，其次调 ATK |
| 高 ATK 让技能失去价值 | 普攻总伤害超过技能总伤害且胜利稳定 | 降 ATK 或提高技能机制价值 |
| MP 用光但收益低 | MP spent 高、damage/interrupt 低 | 降 MP cost、强化提醒或改技能目标 |
| 容错过低 | 普通战真实模型 3 局 2 败 | HP/DEF 小幅上调，或降低敌人爆发 |
| 战斗拖长 | 普通战英雄行动 > 10 | 提高技能使用率或降低敌方总 HP |

## 4. 怪物三档数值基线

| 档次 | HP | Speed | Attack/Power | Defense | 机制数 | 推荐奖励 |
|------|----|-------|--------------|---------|--------|----------|
| I 碎影 | 35-75 | 7-12 | 7-14 | 2-7 | 1 | 普通金币/经验 |
| II 仪式 | 80-135 | 9-14 | 12-22 | 5-11 | 2-3 | 英雄档概率 |
| III 档案化 | 180-280 | 8-15 | 18-36 | 8-16 | 3+阶段 | 传奇/通关奖励 |

数值倍率建议：

| 从 | 到 | HP | 伤害 | 防御 | 奖励 |
|----|----|----|------|------|------|
| I | II | x1.45-x1.75 | x1.25-x1.55 | +2 到 +5 | x1.8 |
| II | III | x1.9-x2.4 | x1.45-x1.8 | +3 到 +7 | x2.2 |

### 4.1 新手副本敌人预算

新手副本不能用“两个机制怪”直接封死路线。第一轮按总 HP 和机制压力控制：

| 节点 | 敌人数量 | 总 HP 预算 | 机制压力 | 说明 |
|------|----------|------------|----------|------|
| 普通怪 | 1-2 个 I 档 | 70-120 | 低 | 教会读条和技能 |
| 宝箱怪 | 1 个 I 档强化或 2 个弱 I 档 | 90-130 | 中 | 胜利后给选择 |
| 精英怪 | 1 个 II 档 | 95-135 | 中高 | 不在 MVP 早期放 2 个 II 档 |
| Boss | 1 个 III 档或 II+召唤机制 | 180-240 | 高 | 至少 8 次英雄行动 |

精英节点第一轮建议只放一个 II 档敌人。若使用两个敌人，两个敌人总 HP 不超过同档单精英预算的 1.25 倍，并且不能同时拥有高爆发读条。

## 7. 需要观察的指标

| 指标 | 用途 |
|------|------|
| 通关率 | 判断整体难度 |
| 单场战斗行动数 | 判断节奏是否拖 |
| AI 非法行动率 | 判断 Prompt 和 schema 是否清楚 |
| BattleLLMSession 重置率 | 判断 session 是否稳定 |
| 静态上下文 token 占比 | 判断是否还在重复输入 |
| MP 不足失败次数 | 判断资源提示是否足够 |
| 冷却误用次数 | 判断模型上下文是否明确 |
| 图鉴信息命中率 | 判断图鉴是否真的影响决策 |
| 羁绊触发次数 | 判断 Build 是否有存在感 |
| 死亡怪物档次分布 | 判断三档风险曲线 |
| 技能使用率 | 判断 Build 和 Prompt 是否让技能成为主体验 |
| basic_attack 占比 | 判断是否退化成普攻模拟器 |
| 连续普攻次数 | 捕捉真实模型注意力衰减 |
| ready skill ignored count | 判断 `ready_skills` 提醒是否有效 |
| 主要承伤来源 | 判断死亡原因是否可解释 |
| Build 成型阶段 | 判断玩家是否经常感到“快胡/已胡” |
| 羁绊触发次数 | 判断 Build 爽感是否进入战斗反馈 |
| Context slot 使用率 | 判断经验成长是否真的影响 Prompt/图鉴/记忆 |

### 7.1 第一轮指标阈值

| 指标 | 普通战 | 精英战 | Boss |
|------|--------|--------|------|
| 英雄行动数 | 4-8 | 6-10 | 8-14 |
| 技能使用率 | >= 35% | >= 40% | >= 45% |
| basic_attack 占比 | <= 60% | <= 55% | <= 50% |
| 连续普攻 | <= 4 次 | <= 4 次 | <= 5 次 |
| ready skill ignored | <= 3 次/战 | <= 4 次/战 | <= 5 次/战 |
| 真实模型非法/降级 | <= 10% | <= 12% | <= 15% |
| Build event | 每 1-2 场至少 1 次 | 每场至少 1 次 | 每场 1-2 次 |

阈值不是最终平衡，而是第一轮“像游戏”的底线。超过阈值时先分析 Prompt、UI 提醒和敌人压力，再改数值。

## 8. 验证方式

| 验证 | 要求 |
|------|------|
| mock model 自动跑 | 至少 50 局固定 seed 集合 |
| 英雄对比 | 每个英雄至少 10 局同副本 seed |
| 怪物档次对比 | I/II/III 同家族战斗统计 |
| 人工试玩 | 至少 3 局，记录体验问题 |
| 真实模型试玩 | BattleLLMSession 稳定后再做，至少 3 局 |
| 非法输出测试 | 构造 JSON 错误、冷却错误、目标错误 |
| 内容校验 | 每次新增内容都跑 schema 校验 |

### 8.1 平衡报告格式

每次调数值后输出一份短报告：

| 字段 | 内容 |
|------|------|
| version | 内容版本、代码提交、seed 集合 |
| hero_summary | 每英雄胜率、平均 tick、平均英雄行动数 |
| action_mix | basic/skill/defend/invalid 占比 |
| skill_usage | 每技能使用次数、ready ignored |
| damage | 输出和承伤来源 top 3 |
| deaths | 死亡来源、死亡 tick、怪物档次 |
| build_progress | Seed/Pair/Online/High Roll/Locked In 次数 |
| context_growth | Strategy/Codex/Memory/Prompt edit 槽位变化 |
| notes | 需要人工判断的问题 |

第一轮不要只看胜率。一个英雄 100% 胜但一直普攻，也是不合格。

---

## 9. 不可做

1. 不在没有完整 run loop 前做过细数值。
2. 不把高通关率直接等同于好玩。
3. 不让模型错误全由数值惩罚解决，优先改 Prompt 和 schema。
4. 不在 MVP 做复杂暴击、闪避、命中体系。
5. 不让 III 档怪物只靠血量变厚。

---

## 10. 验收标准

1. mock model 能完成 50 局批量试跑。
2. 能输出英雄、Build、怪物档次维度的基础统计。
3. 新手副本失败原因可解释。
4. 至少 3 个羁绊在正常路线中能触发。
5. 商店路线和战斗路线都有选择价值。
6. BattleLLMSession 能输出 token/context 复用指标。
7. 每场战报能显示技能使用率、普攻占比、主要承伤来源。
8. Mirel/Korr/Vela 等高风险英雄必须经过固定 seed 对比后再进入玩家默认列表。
9. 批量报告必须显示 Build 成型阶段和 context slot 使用情况。

# G02 战斗系统策划案

> 状态：v0.1 草案  
> 依赖：设计基线、G05 模型行动与 Prompt

---

## 1. 模块目标

建立一个确定性战斗系统：AI 只选择行动，本地引擎负责校验和结算。玩家通过 CLI 观看战斗。

---

## 2. 战斗单位

MVP 单场战斗包含：

1. 1 名英雄。
2. 1-3 名敌人。
3. 每个单位拥有 HP、MP、ATB、speed、attack、defense、power。

---

## 3. 读条机制

每个 tick：

1. 所有存活单位根据 `speed` 增加 `atb`。
2. 某单位 `atb >= 100` 时获得行动机会。
3. 行动后该单位 `atb` 减 100 或清零。
4. 如果是英雄行动，进入模型行动流程。
5. 如果是敌人行动，使用规则 AI。

MVP 不处理多个单位同时满条的复杂优先级，先按 `atb` 高低和固定顺序解决。

---

## 4. 行动类型

使用设计基线固定动作：

| 动作 | 战斗效果 |
|------|----------|
| `basic_attack` | 造成基础伤害 |
| `cast_skill` | 消耗 MP，进入冷却，造成技能效果 |
| `use_item` | 使用道具 |
| `defend` | 获得护盾或减伤 |
| `observe` | 获取或强化敌人信息 |
| `change_stance` | 改变姿态或短期倾向 |

---

## 5. 技能规则

每个技能必须定义：

1. `skill_id`
2. 展示名
3. MP 消耗
4. 冷却
5. 目标规则
6. 标签
7. 结算效果

模型选择技能前必须看到技能是否可用。

---

## 6. 非法行动

| 非法情况 | 处理 |
|----------|------|
| 技能不存在 | 拒绝，改为普通攻击或犹豫 |
| MP 不足 | 拒绝，改为普通攻击或防御 |
| 冷却未好 | 拒绝，记录错误 |
| 目标不存在 | 自动改为合法目标或拒绝 |
| action 格式错误 | 交给 G05 降级策略 |

---

## 7. 战斗胜负

| 条件 | 结果 |
|------|------|
| 所有敌人死亡 | 战斗胜利 |
| 英雄死亡 | 战斗失败 |
| 超过最大 tick | 战斗异常，判定失败或触发调试保护 |

---

## 8. MVP 验收标准

1. 无 LLM 时可用 mock action 跑完战斗。
2. 固定 seed 下战斗结果一致。
3. 冷却和 MP 校验有效。
4. 非法行动不会让程序崩溃。
5. 每次行动都生成战斗日志。

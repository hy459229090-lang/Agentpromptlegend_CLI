# G08 内容数据与 Schema 策划案

> 状态：v0.1 草案  
> 依赖：`02_设计基线与术语表_20260503.md`、G02、G03、G04、G05  
> 目的：让 coding 工具用结构化数据实现内容，而不是把英雄、技能、装备写死在逻辑里。

---

## 1. 模块目标

内容系统负责定义英雄、技能、装备、词条、羁绊、敌人、副本和节点。MVP 要求内容少但结构清楚，方便后续扩展和平衡。

核心原则：

1. 玩法逻辑和内容数据分离。
2. 所有内容使用稳定英文 ID，中文只做展示。
3. 所有引用必须可校验，不能出现悬空 ID。
4. 传奇装备和 Prompt 相关效果必须有明确边界，不能让模型自由发明。

---

## 2. 内容实体

| 实体 | ID 前缀 | 是否 MVP 必需 | 说明 |
|------|---------|---------------|------|
| 英雄 | `hero_` | 是 | 玩家选择和构筑的主体 |
| 技能 | `skill_` | 是 | 战斗行动的主要来源 |
| 装备 | `item_` | 是 | 数值、固定效果、传奇自由度 |
| 词条 | `affix_` | 是 | 构筑修饰与标签来源 |
| 羁绊 | `resonance_` | 是 | 标签组合触发的固定效果 |
| 敌人 | `enemy_` | 是 | 战斗目标和图鉴对象 |
| 副本 | `dungeon_` | 是 | 节点路线集合 |
| 节点 | `node_` | 是 | 普通怪、商店、Boss 等 |
| 状态 | `status_` | 是 | 中毒、流血、护盾等 |

---

## 3. MVP 最小内容量

| 内容 | 最小数量 | 备注 |
|------|----------|------|
| 英雄 | 1 | 先用暗影学徒 |
| 技能 | 3 | 普攻外至少 3 个技能 |
| 敌人 | 3 | 普通怪 2 个，Boss 1 个 |
| 装备 | 6 | 普通 3、英雄 2、传奇 1 |
| 词条 | 6 | 数值、行为、标签、污染都要覆盖 |
| 羁绊 | 2 | 至少 1 个可在 MVP 中触发 |
| 副本 | 1 | 新手副本 |
| 节点 | 5-7 | 固定路线即可 |

---

## 4. 推荐数据文件

具体格式可由实现语言决定，但逻辑上建议拆分：

| 文件 | 内容 |
|------|------|
| `heroes` | 英雄基础属性、默认 Prompt、可用技能 |
| `skills` | 技能消耗、冷却、目标规则、标签、效果 |
| `items` | 装备档次、属性、固定效果、传奇选项 |
| `affixes` | 词条效果、标签、触发条件 |
| `resonances` | 羁绊条件和固定效果 |
| `enemies` | 敌人属性、技能、图鉴阶段 |
| `dungeons` | 副本路线、节点池、Boss |
| `statuses` | 状态效果规则 |

---

## 5. 关键字段要求

### 英雄

必须包含：

1. `id`
2. 展示名
3. 基础属性
4. 默认技能列表
5. 默认英雄 Prompt
6. 默认标签
7. 解锁条件，MVP 可默认为已解锁

### 技能

必须包含：

1. `id`
2. 展示名
3. `mp_cost`
4. `cooldown`
5. `target_rule`
6. `tags`
7. `effect`
8. 模型可见描述

### 装备

必须包含：

1. `id`
2. 展示名
3. `tier`
4. `tags`
5. 属性修正
6. 固定效果
7. 如果是 `legendary`，必须定义 `allowed_effects`

### 敌人

必须包含：

1. `id`
2. 展示名
3. 基础属性
4. 敌人技能
5. 图鉴阶段文本
6. 弱点和抗性
7. 掉落或奖励权重

---

## 6. Schema 校验规则

coding 工具实现时至少要校验：

1. ID 前缀正确。
2. ID 唯一。
3. 引用存在。
4. `tier` 只能是 `common`、`heroic`、`legendary`。
5. 节点类型只能使用设计基线中的 `node type`。
6. 技能目标规则合法。
7. 传奇装备不能缺 `allowed_effects`。
8. 图鉴阶段不能缺失“未知、观察、熟悉、掌握、猎杀”。

---

## 7. 不可做

1. 不要把内容写死在战斗引擎里。
2. 不要让模型看到隐藏字段。
3. 不要让内容数据决定结算之外的随机规则。
4. 不要在 MVP 堆大量内容。

---

## 8. 验收标准

1. 内容数据能加载。
2. 内容数据能校验。
3. 通过内容数据能生成一场战斗。
4. 修改装备或技能数据后，不需要改战斗代码。
5. mock model 能读取模型可见字段，但不能读取隐藏字段。

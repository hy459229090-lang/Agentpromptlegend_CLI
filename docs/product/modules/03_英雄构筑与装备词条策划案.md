# G03 英雄构筑与装备词条策划案

> 状态：v0.3 草案
> 依赖：设计基线、G02 战斗系统、G05 模型行动、G13 内容圣经、G14 TUI
> 本版目标：让英雄种类、Build 类型、装备/词条/Buff/Debuff 明确影响模型决策和玩家选择。

---

## 1. 模块目标

英雄构筑不是只加数值，而是要改变三件事：

1. 玩家选择英雄时能一眼看出战斗风格。
2. Build 会影响武器、技能、目标选择和风险偏好。
3. 模型在战斗 Session 中能读懂“当前构筑应该怎么打”。

核心规则：模型可以根据 Build 做策略选择，但所有数值、触发、伤害、掉落、胜负仍由本地引擎裁判。

---

## 2. Build 组成

| 组成 | 作用 | 是否进入模型上下文 |
|------|------|------------------|
| 英雄职业 | 基础属性、默认 Prompt、可用技能池 | 是，静态上下文 |
| 技能组 | 行动空间、MP、冷却、目标规则 | 是，静态 + 回合 delta |
| 武器 / 装备 | 数值、标签、固定触发、传奇可选效果 | 是，静态上下文 |
| 词条 | 标签、属性、偏好、风险约束 | 是，静态上下文 |
| Buff / Debuff | 当前战斗状态 | 是，每回合 delta |
| 羁绊 / 回响 | 固定被动和战斗开局效果 | 是，静态上下文 |
| 英雄 Prompt | 玩家策略意图 | 是，静态上下文 |
| 图鉴信息 | 已解锁敌人认知 | 是，按可见阶段注入 |

## 3. 英雄池规划

当前实现已有 3 个英雄。下一批规划扩展到 6 个英雄，但 MVP 仍保持“单英雄出战”，不做小队。

| 英雄 | ID | 定位 | 主标签 | 视觉短标识 | 决策倾向 |
|------|----|------|--------|------------|----------|
| 暗影学徒 Astia | `hero_shadow_apprentice` | 法术、腐化、打断 | shadow/control/risk | `[CNDL]` | 用 MP 换节奏，优先打断咏唱 |
| 灰烬守卫 Norn | `hero_ash_guardian` | 护盾、反击、稳定 | guard/shield/counter | `[SHLD]` | 保持 HP 安全线，吃下关键伤害 |
| 裂弦猎手 Vela | `hero_broken_string_hunter` | 流血、高速、收割 | bleed/speed/execute | `[XBOW]` | 制造行动差，击杀低血量目标 |
| 瘟沼先知 Mirel | `hero_mire_oracle` | 毒、预言、延迟收益 | poison/omen/attrition | `[VENM]` | 先铺毒和预兆，拖长战斗兑现收益 |
| 坟场工匠 Korr | `hero_gravewright` | 装置、召唤、爆破 | construct/trap/burst | `[GEAR]` | 布置代理物，等待触发窗口爆发 |
| 失声唱诗者 Sera | `hero_echo_exile` | 治疗、净化、回声 | echo/cleanse/support | `[ECHO]` | 保持状态清洁，复制或延长关键 Buff |

新增英雄优先级：

| 优先级 | 英雄 | 原因 |
|--------|------|------|
| P0 | 瘟沼先知 | 补齐毒/持续伤害 Build，支持怪物抗性和图鉴玩法 |
| P1 | 坟场工匠 | 提供装置/召唤类构筑，测试本地裁判复杂触发 |
| P2 | 失声唱诗者 | 提供治疗/净化/回声复制，适合更长副本后加入 |

## 4. Build 类型

Build 类型是给玩家和模型共同理解的“打法标签”。一个英雄可以支持 1-3 个 Build 类型。

| Build 类型 | 核心标签 | 偏好武器 | 偏好技能 | 模型决策倾向 | 克制 | 被克制 |
|------------|----------|----------|----------|--------------|------|--------|
| 黑烛打断 | shadow/control | 短杖、典籍 | silence、hex、shadow damage | 盯住高 ATB 和咏唱敌人 | 法师、Boss 蓄力 | 高抗性护盾 |
| 铁壁反击 | guard/shield/counter | 塔盾、重甲 | shield、counter、taunt | HP 低于阈值先防守，敌人蓄力时反击 | 高爆发单体 | 毒和持续伤害 |
| 裂弦收割 | bleed/speed/execute | 弩、钩刃 | bleed、execute、evade | 先打断，再击杀低血量目标 | 脆皮、高速敌 | 厚甲和反伤 |
| 毒沼消耗 | poison/omen/attrition | 毒瓶、湿典 | poison、slow、omen | 先铺状态，避免过早换目标 | 高防低速敌 | 快速爆发敌 |
| 回声爆发 | echo/burst | 回声铃、裂镜 | copy、charge、release | 等待 Echo 层数后集中爆发 | Boss 阶段战 | 短战斗 |
| 图鉴猎手 | codex/observe | 透镜、档案针 | scan、mark、exploit | 优先观察未知敌人，再针对弱点行动 | 新怪、精英怪 | 已熟悉低威胁怪 |
| 献祭契约 | sacrifice/corruption | 黑烛契约物 | hp_cost、risk_power | 可用 HP 换节奏，但低血量必须收敛 | 紧急破局 | 长期消耗 |
| 装置代理 | construct/trap | 齿轮、坟钉 | deploy、trigger、detonate | 先布置，后引爆或转移仇恨 | 多怪波次 | 快速斩首 |

---

## 5. 装备三档

| 档次 | 设计目标 | 模型自由度 | 示例 |
|------|----------|------------|------|
| 普通 common | 清晰数值、低学习成本 | 无自由度 | `power +3`、`speed +2` |
| 英雄 heroic | 更高数值 + 固定触发 | 低自由度，触发条件固定 | 开战护盾、首次打断追加沉默 |
| 传奇 legendary | 强数值 + 限定可选效果 | 中自由度，只能从 `allowed_effects` 选择 | 对 Boss 选破甲，对小怪选溅射 |

传奇装备必须写清：

1. `allowed_effects`
2. 触发窗口
3. 适用目标
4. 数值上限
5. 不允许模型发明的边界

## 6. 词条类型

| 类型 | 作用 | 示例 |
|------|------|------|
| 数值词条 | 改属性 | `power +3`、`speed +2` |
| 标签词条 | 触发 Build / 羁绊 | 增加 `shadow`、`guard` |
| 行为词条 | 改模型偏好 | 未知敌人优先观察 |
| 风险词条 | 让策略带代价 | HP 低时伤害高但防御低 |
| 污染词条 | 死亡、复活、黑烛事件带来的负面策略 | 更倾向攻击最低血量敌人 |
| 图鉴词条 | 提高研究、标记、克制能力 | 新敌首回合获得 `codex_mark` |

行为词条只能作为模型上下文的偏好，不得直接强制模型输出非法行动。

## 7. Buff / Debuff 体系

Buff / Debuff 必须同时服务数值结算、模型决策和 UI 可读性。

### 7.1 Buff

| 状态 | ID | 效果 | 模型应如何理解 |
|------|----|------|----------------|
| 护盾 | `status_shield` | 吸收伤害 | 可承受风险，适合换节奏 |
| 凝神 | `status_focus` | 下一次技能 power 增强 | 等待高价值技能窗口 |
| 急速 | `status_haste` | ATB 获取提高 | 更适合打断和收割 |
| 守势 | `status_guard` | 防御提高，可触发反击 | 优先保护 HP 安全线 |
| 回声充能 | `status_echo_charge` | 累积后释放额外效果 | 不要过早消耗爆发 |
| 潜行 | `status_stealth` | 下次攻击更强或降低受击 | 适合收割或避开仇恨 |
| 图鉴标记 | `status_codex_mark` | 对已标记目标获得克制 | 优先攻击被标记目标 |

### 7.2 Debuff

| 状态 | ID | 效果 | 模型应如何理解 |
|------|----|------|----------------|
| 腐化 | `status_corruption` | 影/毒类持续风险或易伤 | 适合暗影 Build 继续叠加 |
| 流血 | `status_bleed` | 回合流失 HP | 适合收割 Build 保持压力 |
| 中毒 | `status_poison` | 低速长期伤害 | 适合拖长战斗 |
| 沉默 | `status_silence` | 限制咏唱/技能 | 高价值控制，优先给法师 |
| 破甲 | `status_exposed` | 防御下降 | 爆发前优先施加 |
| 失衡 | `status_stagger` | ATB 降低或行动延迟 | 打断即将行动的敌人 |
| 厄兆 | `status_omen` | 若未处理，若干回合后触发惩罚 | 需要 UI 明确倒计时 |
| 灼烬 | `status_ember` | 受击或行动时触发小伤害 | 适合反击/护盾 Build |

## 8. 羁绊 / 回响

羁绊由标签触发，效果固定，不能由模型自由解释。

| 羁绊 | 条件 | 效果 | 适合 Build |
|------|------|------|------------|
| 腐化学派 | `shadow >= 3` | 腐化目标受到暗影技能时额外伤害 | 黑烛打断 |
| 铁色军团 | `guard >= 2` + `armor >= 2` | 开战护盾，护盾存在时反击增强 | 铁壁反击 |
| 猎杀仪式 | `hunter >= 2` + `execute >= 1` | 攻击低血量敌人追加伤害 | 裂弦收割 |
| 瘟沼祷言 | `poison >= 2` + `omen >= 1` | 中毒敌人行动后追加厄兆层数 | 毒沼消耗 |
| 回声合唱 | `echo >= 3` | 第三次非基础技能复制 40% 效果 | 回声爆发 |
| 档案猎杀 | `codex >= 2` | 已掌握图鉴目标受到额外克制效果 | 图鉴猎手 |
| 黑烛献祭 | `sacrifice >= 2` | 消耗 HP 的技能获得额外 power，但提高污染 | 献祭契约 |
| 坟钉机关 | `construct >= 2` | 装置首次触发时附加失衡 | 装置代理 |

## 8.1 Build 胡牌体验

Build 的目标不是“数值堆叠”，而是让玩家感到自己在凑一套牌。每次拿装备、词条、技能升级时，UI 必须告诉玩家：

1. 当前 Build 已经在哪个阶段。
2. 哪些标签已经成型。
3. 差什么能触发下一个羁绊。
4. 这次选择会让下一场战斗有什么变化。

### 8.1.1 成型阶段

| 阶段 | 条件 | UI 文案 | 战斗反馈 |
|------|------|---------|----------|
| Seed | 拿到 1 个核心标签 | `Build seed found` | Build hint 出现 |
| Pair | 核心标签达到 2 | `Pair online` | 小触发日志 |
| Online | 触发 1 个羁绊 | `RESONANCE ONLINE` | 动作帧强调 |
| High Roll | 核心装备 + 2 词条 + 羁绊 | `BUILD HIGH ROLL` | 背景/动作加强 |
| Locked In | 2 个羁绊或关键传奇 | `BUILD LOCKED` | 结算卡片展示 |

### 8.1.2 差几张提示

Build 面板必须显示“差几张胡”：

```text
BUILD :: BLACK CANDLE INTERRUPT

Core tags
shadow  [###] 3/3  online
control [##-] 2/3  need 1
risk    [#--] 1/2  optional

Active
[R] Corruption School

Near
[ ] Candle Tribunal needs control +1

Best next picks
- Hexed Wick affix       control +1
- Black Sun Codex        shadow +1, codex +1
```

### 8.1.3 胡牌事件

触发羁绊时必须有独立事件帧：

```text
BUILD EVENT :: RESONANCE ONLINE

[R] Corruption School
shadow(3) + control(2)

Effect
Corrupted enemies take +4 shadow damage.

Astia's candle burns black.
```

验收：

1. 玩家拿奖励时能看到“这张牌是否补齐 Build”。
2. 羁绊触发时有 UI 和战斗日志反馈。
3. 战报能列出本场触发过的 Build event。

## 9. Build 对模型选择的影响

Prompt Composer 必须把 Build 转译为清晰的策略提示，而不是只列数据。

推荐格式：

```text
BUILD PLAN
Archetype: Bleed Execution
Priority:
1. Keep bleed on the toughest enemy.
2. Interrupt enemies above 80% ATB if they can cast.
3. Execute enemies below 35% HP.
Avoid:
- Do not spend Hook Break on full-HP targets.
- Do not attack shielded enemies unless no better target exists.
```

验收标准：

1. Build 改变后，Prompt 中的 `Archetype` 和 `Priority` 必须变化。
2. 装备/词条必须改变至少一个策略提示或一个可见数值。
3. UI 中必须显示当前 Build 类型、核心标签、触发中羁绊。

## 10. 下一阶段实现优先级

| 优先级 | 内容 | 理由 |
|--------|------|------|
| P0 | Build 类型字段、UI 展示、Prompt 转译 | 直接解决“Build 不影响选择”的问题 |
| P0 | Buff/Debuff 统一 ID、描述、显示符号 | 后续怪物和图鉴都依赖 |
| P1 | 新增 3 个英雄规划和内容数据 | 增加选择，但不能先于 Build 解释 |
| P1 | 羁绊触发日志和战斗面板显示 | 提升构筑存在感 |
| P2 | 传奇装备 allowed_effects 的模型选择窗口 | 有趣但需要裁判和测试约束 |

---

## 11. 验收标准

1. 至少 6 个英雄有职业、Build 倾向、视觉短标识和默认 Prompt。
2. 至少 8 类 Build 有明确标签、武器、技能和模型决策倾向。
3. Buff/Debuff 有统一 ID、效果、UI 短名和模型解释。
4. 装备、词条、羁绊能影响 Prompt 和本地结算。
5. 英雄选择、英雄详情和战斗主屏能展示 Build 信息。

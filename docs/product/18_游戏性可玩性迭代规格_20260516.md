# Ouro Agent 游戏性可玩性迭代规格

> 版本：v0.1
> 日期：2026-05-16
> 来源：2026-05-16 mock 完整试玩、批量试跑、既有 G16/G17 体验规格
> 目的：在不改变“单英雄、战斗中自动行动、本地裁判结算”的前提下，把当前可运行版本推进到更有选择、更有风险收益、更有复盘欲望的可玩版本。

---

## 1. 本轮试玩结论

当前版本已经不再是纯日志 Demo：主菜单、英雄卡、左右对战画面、动作帧、战报、路线和奖励都能被玩家看见。

主要问题从“有没有反馈”变成了“反馈是否形成决策闭环”：

1. 路线、商店、休息和奖励已经出现，但收益差异偏弱，玩家难以判断为什么选 A 而不是 B。
2. Build 面板能提示“还差几张”，但奖励项没有足够明确地展示“选完后阶段如何变化、下一战打法如何变化”。
3. MP 和续航对胜负影响很强，但战斗外缺少足够直观的恢复、压缩战斗时长或转换资源的选择。
4. 防御型英雄有安全感，但在 Boss 战可能进入长时间低输出循环，观战疲劳明显。
5. 敌人已经有档次和动作，但机制教学不足。玩家看到失败时，知道自己倒下了，却不一定知道下一局该改变什么。
6. `--lang` 只能作为全局参数放在子命令前，对新玩家不够宽容。

## 3. 可玩性目标

下一阶段不以“增加更多内容”为第一目标，而以“每一次选择都能让玩家预期下一场战斗如何不同”为目标。

| 目标 | 玩家感知 | 验收方向 |
|------|----------|----------|
| 选择更有意义 | 路线、奖励、商店、休息都有清晰风险收益 | 选择页展示预期影响，战报回指本次选择贡献。 |
| Build 更爽 | 从 Seed 到 High Roll 的变化可见，并改变模型倾向 | 奖励前后展示阶段变化、羁绊进度、推荐打法变化。 |
| 战斗更短更锋利 | 普通战 3-8 英雄回合，精英战 6-14 英雄回合，Boss 战不拖入低输出循环 | batch 报告新增战斗时长分布和超时原因。 |
| 失败更可学 | 失败不是只告诉死亡，而是指出资源、目标、路线或 Build 决策问题 | 失败战报给出 1-3 条基于 trace 的下一局建议。 |
| 怪物更像机制 | 敌人不只是 HP/伤害包，而有可观察、可反制的行为 | 首见预兆、战中提示、图鉴更新三段式教学。 |

## 4. 设计规格

### 4.1 路线选择

路线卡必须从“节点列表”升级为“风险收益决策”。

每个可选节点至少展示：

1. 风险等级：safe / low / medium / high / boss。
2. 预期消耗：HP、MP、回合数或异常风险。
3. 主要收益：金币、经验、装备、词条、图鉴、恢复、Prompt 槽。
4. 对当前 Build 的适配：`synergy`、`neutral`、`danger`。
5. 已知敌方机制：只显示图鉴已解锁或战前侦察能看到的信息。

示例：

```text
[1] [M] 鼠群
    risk: low       cost: HP chip / MP safe
    reward: 20g, 15xp, poison tag chance
    build: neutral; helps Mirel, weak for Astia
    scout: two fast bodies, low HP, no chant
```

### 4.2 奖励选择

奖励卡必须显示“拿之前”和“拿之后”的 Build 变化。

必须展示：

1. 属性变化：HP/MP/ATK/DEF/POW。
2. 标签变化：新增标签与当前计数。
3. 阶段变化：例如 `[ONLINE] -> [HIGH]`。
4. 下一战策略影响：模型更可能打断、守护、收割、消耗或观察。
5. 若奖励与当前英雄不适配，也要明确说“这是跨 Build 种子”。

### 4.3 商店和休息

商店不应只是奖励列表换皮，必须承担局内修正功能。

MVP+ 商店功能优先级：

1. 买恢复：HP、MP 或一次性护盾。
2. 买定向标签：补足当前最近羁绊的 1 个缺口。
3. 换 Prompt 风格：在 Aggressive / Guarded / Control / Attrition 间调整。
4. 买侦察：提前显示下一层一个隐藏节点或 Boss 机制关键词。

休息必须有至少两个互斥选项：

1. Recover：恢复 HP/MP。
2. Focus：下一战开局获得 focus 或护盾。
3. Study：推进图鉴或解锁一条敌方机制提示。

### 4.4 战斗节奏

普通战、精英战、Boss 战必须有不同节奏目标。

| 战斗类型 | 目标英雄回合 | 设计要求 |
|----------|--------------|----------|
| 普通战 | 3-8 | 快速展示 Build 核心循环，不拖长。 |
| 精英战 | 6-14 | 至少出现一次机制反制机会。 |
| Boss 战 | 10-28 | 有阶段和反制窗口；不允许长期只剩普攻磨血。 |

如果战斗超过目标区间，战报必须给出“拖长原因”：

1. MP 枯竭。
2. 输出不足。
3. 防御循环。
4. 未打断蓄力。
5. 敌方护盾/治疗。

### 4.5 模型策略与 Prompt

Prompt 模板不能只改文案，必须改 mock/真实模型可见策略优先级。

每个模板必须至少影响：

1. 低血敌人收割阈值。
2. 高 ATB / 蓄力敌人打断阈值。
3. 自身低血时防御或护盾阈值。
4. MP 保留阈值。

战报必须显示本场模板带来的 1 条关键行为，例如：

```text
Prompt impact: Control template spent 18 MP to interrupt a 92 ATB chant.
```

### 4.6 失败复盘

失败战报必须从 trace 中归因，而不是只输出死亡句。

最少归因维度：

1. 资源：MP 枯竭、HP 续航不足、冷却空窗。
2. 目标：过度攻击低威胁目标、未优先打断蓄力目标。
3. Build：当前奖励没有补足关键标签或输出短板。
4. 路线：连续战斗后未休息、过早挑战精英/Boss。

输出格式：

```text
失败原因
1. MP 0/72 后连续 4 次普攻，未能完成收割。
2. 上一层选择金币奖励，没有补足 guard/armor 续航缺口。
3. 下一局建议：休息选 Recover，或奖励优先拿 guard + armor。
```

## 6. 非目标

本轮可玩性迭代不做：

1. 小队系统。
2. 战斗中手动选择技能或目标。
3. 在线排行榜。
4. 真实联网商店或付费系统。
5. 大型剧情文本扩写。
6. 大规模内容包堆量。

核心仍是：玩家在战斗外配置 Agent，战斗中观察模型决策，本地规则确定结算。

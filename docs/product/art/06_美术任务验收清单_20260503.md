## 2. 实现验收

| 验收项 | 标准 |
|--------|------|
| ASCII-safe | Windows PowerShell 可读 |
| no-color | 不依赖颜色表达状态 |
| Unicode-enhanced | 可选，不影响 ASCII 默认 |
| 性能 | 动画可关闭，主屏可快照测试 |
| 战斗信息 | HP、MP、ATB、状态、模型行动、裁判结果清楚 |
| Token 展示 | Echo Cost / Ritual Time 不抢占战斗信息 |
| 角色识别 | 6 个英雄都必须能从主道具和短标识识别职业 |
| 战斗短标识 | Astia/Norn/Vela/Mirel/Korr/Sera 分别使用 `[CNDL]`、`[SHLD]`、`[XBOW]`、`[VENM]`、`[GEAR]`、`[ECHO]` |
| Build 可读 | 英雄详情必须显示 Build 类型、核心标签、装备和羁绊 |
| 怪物可读 | 敌人必须显示 tier + glyph + codex stage |
| Session 可读 | BattleLLMSession 信息必须低优先级展示，不抢 HP/MP/ATB |
| 动作反馈 | 每个 hero/enemy turn 必须有动作短句、目标、影响和 Judge 摘要 |
| 战报可读 | 每场战斗结束显示技能使用率、普攻占比、主要伤害来源、死亡原因 |
| 交互可见 | 路线、奖励、商店在默认试玩模式下必须显示选择项 |
| no-animation | 关闭动画只关闭延迟和微动画，不得关闭 turn frame |
| 图鉴卡片 | Codex 必须有 locked/fog/observed/mastered 卡片状态 |
| Build 胡牌 | Build 必须展示成型阶段、active/near/best next picks |
| 动作资产 | 每英雄和 MVP 怪物必须有 idle/cast/attack/hit/death 等动作状态 |
| Context UI | Strategy/Codex/Memory/Prompt edit 槽位必须可见 |
| 左右对战 | 战斗主屏必须左英雄、右怪物，中间有技能/弹道/命中效果层 |
| 战斗精灵 | 英雄和 MVP 怪物必须有 4-6 行 idle/cast/attack/hit/death 等精灵帧 |
| 武器图标 | 武器必须显示类型图标和轮廓，例如 `[W:STF] c==*` |
| Build 徽章 | Build 必须显示 `[SEED]`、`[PAIR]`、`[ONLINE]`、`[HIGH]`、`[LOCK]` 阶段 |

## 3. 不通过条件

1. 输出刷屏到无法阅读。
2. 颜色关闭后看不懂风险或状态。
3. ASCII 图过大影响战斗面板。
4. Token 信息比战斗信息更突出。
5. 快照测试无法稳定比较。
6. 玩家只看头像和短标识时无法判断英雄职业。
7. 战斗只显示最终画面，没有实时动作帧。
8. 路线、奖励、商店默认静默自动选择。
9. 图鉴只是文字列表，没有卡片和迷雾。
10. Build 只有数值，没有胡牌反馈。
11. 角色只有头像，没有动作和状态。
12. 战斗画面没有左右对战站位。
13. 技能只是日志文字，没有中央弹道/命中/格挡效果。
14. 武器、Build、技能没有图标和视觉层级。

# Ouro Agent 像素风 TUI 美术研发边界与需求规格

日期：2026-05-16

> 2026-05-16 追加结论：本文件定义的 ASCII pixel panel 只保留为兼容 fallback 和过渡层。推荐体验与后续实现以 `22_TUI图形化Canvas美术研发规格_20260516.md` 为准，即终端低分辨率 Canvas、Unicode block sprite、块面弹道和可选 ANSI 主题。

## 1. 目标

把当前 CLI/TUI 从“字符拼接的信息屏”升级为“ASCII-safe 像素仪式战斗板”。

视觉升级必须服务玩法理解：

1. 让自动战斗成为可读谜题。
2. 让反制窗口有悬念。
3. 让高潮击杀有舞台感。
4. 让 Build 成长可期待。
5. 让失败复盘能指导下一局。

## 2. 技术边界

默认不引入 Rich/Textual/curses。

原因：

1. 当前 Slice 0/A 要求 mock、CI、安装和快照稳定。
2. 默认输出必须 ASCII-safe、no-color 可读。
3. Textual 更适合后续独立 `ouro tui` 全屏模式，不适合替换默认 CLI 输出。
4. Rich/ANSI 可以后续作为可选增强层，但不能成为语义依赖。

当前首批方案：

1. 自研轻量像素 UI Kit。
2. 纯 ASCII 面板和状态边框。
3. 固定宽度 80/100/120 快照保障。
4. TUI 只显示状态，不修改战斗规则。

## 3. 视觉主题

主题名：`THE ECHO ALTAR`

中文名：`回声祭坛`

玩家配置英雄 Agent，英雄在终端祭坛中自动作战。模型行动是“回声判词”，本地引擎是“裁决律”。

关键词：

1. Altar：战斗舞台像祭坛。
2. Trace：模型行动像被记录的回声。
3. Seal：反制窗口像封印打开。
4. Rupture：高潮击杀像裂隙爆发。
5. Ash：失败状态像屏幕燃尽。

## 4. 面板系统

### 4.1 Stage Panel

用于战斗主舞台。首屏最上方，左英雄、中心效果 lane、右敌人。

验收：

1. 100/120 列模式显示 `THE ECHO ALTAR` / `回声祭坛`。
2. 反制状态用 `>====<` 边框。
3. 高潮状态用 `#====#` 边框。
4. 危险/错失状态用 `!----!` 边框。

### 4.2 Director Panel

用于本回合主焦点。

必须包含：

1. ACTION / 行动
2. INTENT / 意图
3. RISK / 风险
4. ALIGN / 契合
5. IMPACT / 影响
6. COUNTER / 反制（有窗口时）

验收：

同一屏不得重复出现两组完整 ACTION / INTENT / RISK / ALIGN。

### 4.3 Battle Thesis Panel

用于战斗谜题。

必须包含：

1. GOAL / 目标
2. CLOCK / 威胁
3. FAIL IF / 失败条件
4. NEXT / 下一步

验收：

玩家在 3 秒内能说出“这回合最怕什么，以及下一步应该期待什么”。

### 4.4 Evidence Panel

用于模型证据和低优先级日志。

包含：

1. 模型意图摘要
2. Battle Echo / Sealed Echo / Fresh Echo
3. Echo Cost / Ritual Time
4. Action Strip
5. 最近 3 条日志

验收：

证据区不能抢 ACTION 和 Stage 的视觉焦点。

### 4.5 Card Panel

用于路线、奖励、Build、休整。

每张卡必须说明：

1. Badge：`[REC]`、`[DANGER]`、`[GREED]`、`[SAFE]`、`[FLEX]`
2. Reward / Danger / Why
3. Build Before -> After
4. New Behavior / 下一场行为变化

## 6. 禁止项

1. 不用图片转 ASCII。
2. 不依赖 Nerd Font、emoji、Braille。
3. 不让颜色承载唯一语义。
4. 不用 TUI 修改战斗规则。
5. 不让 `--no-animation` 退化成最终快照。
6. 不在 `screens.py` 继续散落新 sprite 资产。

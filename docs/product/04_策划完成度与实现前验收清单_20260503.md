## 4. 第一轮实现验收

Slice A 完成标准：

1. 无真实 API key 也能运行。
2. mock model 能参与英雄行动。
3. 英雄和敌人按读条行动。
4. 英雄行动必须通过 action schema。
5. 本地裁判能校验 MP、冷却、目标。
6. 非法 action 有降级或惩罚。
7. 战斗能胜利或失败。
8. 战斗结束能输出 trace。
9. Slice A 中 `REQ-*` 的状态能根据实现结果更新。
10. 每个完成需求都有测试、trace 或日志证据。
11. `ouro --version` 可运行。
12. `ouro play --mock` 不需要 API key。
13. `ouro config show` 不显示 API key 明文。
14. ASCII-safe 战斗主屏可读。

## 5. 当前开放问题

这些问题不阻塞第一轮 coding，但需要在进入完整 MVP 前确认：

1. 技术栈选择。
2. 第一版 CLI/TUI 库选择。
3. 内容数据格式：JSON、YAML 还是代码内 fixture。
4. 真实模型接入的 provider 范围。
5. Prompt 容量和策略槽的具体升级数值。
6. 污染复活在 MVP 是否开启，还是先只做策划预留。

---

## 7. 标准对齐 Gate

进入 coding 前必须满足：

| Gate | 要求 |
|------|------|
| GDD Gate | 玩法目标、玩家体验、系统规则、不可做和验收标准明确 |
| Requirement Gate | 本轮需求已写入 `06_需求追踪矩阵_20260503.md` |
| Evidence Gate | 每个需求有测试、trace、日志或试玩记录作为证据类型 |
| Scope Gate | 本轮不做项明确写出 |
| Change Gate | 需求变更必须更新追踪矩阵和设计基线 |

---

## 6. 防跑偏提醒

1. 不要先做排行榜。
2. 不要先做复杂 UI。
3. 不要先接真实模型。
4. 不要让模型决定伤害或掉落。
5. 不要做小队。
6. 不要把游戏做成评测报告生成器。

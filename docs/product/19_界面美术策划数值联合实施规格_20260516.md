# Ouro Agent 界面美术、策划与数值联合实施规格

> 版本：v0.1
> 日期：2026-05-16
> 来源：2026-05-16 mock 完整试玩、`18_游戏性可玩性迭代规格_20260516.md`
> 目标：把后续迭代从“功能能显示”推进到“界面效果优秀、模块排布稳定、策划选择清楚、数值节奏可控”。

---

## 1. 总目标

下一阶段的验收目标不是“多加几个页面”，而是让所有玩家可见模块达到稳定好看的界面效果：

1. 主菜单、英雄、路线、奖励、商店、休息、战斗、战报、图鉴、批量报告都使用统一卡片和面板语言。
2. 80 列、100 列、120 列三档宽度下不出现关键文本错位、断栏、遮挡或信息被挤出。
3. 每个界面只突出当前最重要的玩家决策，技术字段保持可见但低优先级。
4. 数值节奏要服务界面观感：普通战短、精英战有机制、Boss 战有阶段和破局窗口。
5. 所有新界面必须可截图、可快照测试、可 no-color 阅读、可 `--no-animation` 复现。

## 2. 实际试玩暴露的问题

| 位置 | 问题 | 影响 | 改进方向 |
|------|------|------|----------|
| 战斗主屏 | `下次选择` 一行过长，在窄宽下挤压右侧信息 | Build 信息可读性下降 | 拆为 `NEXT PICK` 与 `NEED` 两行，最多显示 2 个主推荐。 |
| 战斗主屏 | 敌方状态长 ID 会截断或挤到边框 | 状态识别不稳定 | 主屏显示短名，详情/trace 保留完整 ID。 |
| 战斗主屏 | 敌人队列、模型思考、日志同时出现时密度偏高 | 玩家不知道先看哪里 | 分层：动作结果最高，模型思考折叠为 2 行，日志 4-5 行。 |
| 路线选择 | 路线能选，但风险收益不够可比较 | 玩家选择像默认流程 | 增加风险、预期消耗、收益、Build 适配、侦察信息。 |
| 奖励选择 | 奖励能拿，但缺少前后 Build 变化 | 胡牌爽感弱 | 显示 `before -> after`、标签计数和策略影响。 |
| 商店/休息 | 作为节点存在，但局内修正功能不强 | 失败后缺少可执行改法 | 商店卖恢复/定向标签/侦察/Prompt；休息三选一。 |
| 战报 | 有行动统计，但失败归因还粗 | 玩家知道输了，不知道下局怎么改 | 从 trace 输出资源、目标、Build、路线归因。 |
| 数值节奏 | 诺恩 Boss 战出现 600 ticks 超时 | 防御 Build 观战疲劳 | 增加防守转输出窗口、Boss 破防/狂暴/处决规则。 |
| CLI 可用性 | `ouro menu --lang zh` 报错 | 新玩家容易踩参数顺序坑 | 支持子命令后全局参数或给出明确提示。 |

## 3. 统一视觉结构

所有界面按 5 层组织，不允许每个页面各自发明布局。

| 层级 | 名称 | 内容 | 规则 |
|------|------|------|------|
| L1 | Header | 游戏名、场景、模式、seed、provider | 1-3 行，不能挤占主体。 |
| L2 | Primary | 当前核心对象：英雄、敌人、路线、奖励、Boss | 占最多空间，必须一眼可读。 |
| L3 | Decision | 玩家要做的选择或模型刚做的行动 | 只放当前最重要的 1 个决策/行动。 |
| L4 | Support | Build、图鉴、Prompt、Session、数值摘要 | 信息短，低密度。 |
| L5 | Log/Evidence | 最近日志、trace、测试/批量指标 | 最多 4-6 行，不能替代主体画面。 |

### 3.1 宽度档位

| 档位 | 目标 | 规则 |
|------|------|------|
| 80 列 | 最低可玩 | 双栏压缩，去掉长描述，保留 HP/MP/ATB/行动/日志。 |
| 100 列 | 默认推荐 | 左右对战、Build、Session、日志同时可见。 |
| 120 列 | 展示/录屏 | 可显示更多敌方队列、图鉴提示、Build 推荐。 |

硬性要求：

1. 任一档位不得出现边框错位。
2. 任一档位不得让 HP/MP/ATB、行动结果、目标、胜负原因缺失。
3. 长文本必须先压缩、再换行，不允许撑破面板。
4. 中英文都必须验收；中文宽字符不能破坏卡片宽度。

## 4. 模块级界面目标

### 4.1 主菜单

目标：玩家一打开就知道当前能不能玩、该从哪里开始。

必须展示：

1. Provider / model / key 状态。
2. mock 试玩入口。
3. New Run / Heroes / Prompt / Config / Replay / Codex。
4. 最近 trace 或最近 run。

视觉要求：

1. 状态区和入口区分栏。
2. 入口使用编号和短命令，不写大段说明。
3. 若真实 provider key 已设置，仍要突出 mock 可用，避免新玩家担心成本。

### 4.2 英雄与 Build

目标：让玩家只看英雄卡就能判断打法、风险和成长方向。

必须展示：

1. 头像 / 短标识 / 职业。
2. 武器图标 `[W:*]` 和轮廓。
3. Build 阶段 `[SEED]` / `[PAIR]` / `[ONLINE]` / `[HIGH]` / `[LOCK]`。
4. 技能 MP/CD/用途。
5. 已激活羁绊、接近羁绊、推荐选择。
6. AI 倾向和 Prompt 风格。

排布规则：

1. 英雄列表只显示摘要，不塞完整技能描述。
2. 英雄详情用三块：`IDENTITY`、`BUILD MAP`、`AI PLAN`。
3. 推荐选择最多显示 3 条，超出进详情页。

### 4.3 路线选择

目标：路线不是列表，而是风险收益卡。

每个路线卡必须包含：

1. 节点类型图标：`[M]`、`[$]`、`[+]`、`[?]`、`[B]`。
2. 风险：safe / low / medium / high / boss。
3. 预期消耗：HP、MP、回合数、异常风险。
4. 收益：金币、经验、装备、词条、图鉴、恢复、侦察。
5. Build 适配：synergy / neutral / danger。
6. 侦察：只显示可见或已解锁信息。

### 4.4 奖励选择

目标：奖励必须让玩家看到“拿了以后发生什么”。

奖励卡结构：

```text
+-- [1] AFFIX ------------------------------------------------
| Corrupted Focus
| Stats : POW +3
| Tags  : shadow 5 -> 6, corruption 1 -> 2
| Build : ONLINE stays; control still needs +1
| AI    : more likely to spend MP on shadow skills
+-------------------------------------------------------------
```

规则：

1. 每张奖励卡最多 6 行。
2. 必须显示前后变化，不只显示 item 描述。
3. 若奖励不适配当前 Build，要明确标记 `cross-seed` 或 `future build`。

### 4.5 商店与休息

目标：商店和休息承担“纠错”和“转向”功能。

商店四类货架：

1. Recover：HP/MP/护盾。
2. Build：定向标签、替换装备、补羁绊缺口。
3. Prompt：切换风格或加策略槽。
4. Scout：显示下一层风险或 Boss 关键词。

休息三选一：

1. Recover：恢复 HP/MP。
2. Focus：下一战开局 focus/护盾。
3. Study：推进图鉴或得到机制提示。

### 4.6 战斗主屏

目标：非常好的界面效果必须首先体现在战斗主屏。

默认 100 列结构：

```text
OURO AGENT :: EMBER CRYPT :: FLOOR 3                         AUTO WATCH
Seed: mvp_a-007        Provider: mock        Speed: x1

+---------------- HERO ----------------+      +-------------- ENEMY --------------+
| [CNDL] ASTIA                         |      | [II:k] FIREKEEPER                 |
|   .^.                                | ---> |    (k)                            |
|  /|c|==*                             | -16 |   /|w|\                           |
|   / \                                | SLN |    / \                            |
| HP [#####---] 62/100  MP [###---]    |      | HP [###-----] 31/90  ATB [##----] |
| ATB [######]  BUFF: SHD(8)           |      | DEBUFF: SLN(1), CRP(2)            |
+--------------------------------------+      +-----------------------------------+

ACTION  Hex Seal -> Firekeeper | valid | -16 shadow, silence(1)
BUILD   [ONLINE] shadow 5/3 control 2/3
NEXT    control +1 for HIGH ROLL | guard + armor for survival
ECHO    mock | Echo Cost 0 | Ritual Time 12ms
LOG     Astia seals the chant. Firekeeper loses its release window.
```

排布规则：

1. `ACTION` 必须在 Build、Session、Log 之前。
2. Build 行最多两行；推荐项过长则只保留 top 2。
3. Session 信息一行化，不得抢屏。
4. 模型思考默认 2 行，详情进入 trace 或 replay。
5. 敌人多于 1 个时，主面板展示当前目标，敌方队列压缩到 2-4 行。

### 4.7 Boss 战

目标：Boss 必须像一场特殊战斗，而不是 HP 更厚。

Boss 界面新增：

1. Phase：阶段名和阈值。
2. Charge：蓄力进度和可反制窗口。
3. Break：破防条或打断条件。
4. Enrage：拖长后的压力提示。

数值要求：

1. Boss 战目标 10-28 个英雄行动。
2. 不允许只靠普攻磨 40+ 回合。
3. 防御型英雄必须有反击、破防、反伤或处决窗口。

### 4.8 战报与失败复盘

目标：战报既好看，又能指导下一局。

战报结构：

1. Result：胜利/失败/超时。
2. Tempo：ticks、英雄回合、敌人回合、是否超出目标区间。
3. Action Mix：技能、普攻、防御、观察。
4. Damage：主要输出/承伤来源。
5. Build：本场触发、接近、错过的胡牌点。
6. Prompt：模板影响的关键行动。
7. Failure Lesson：失败时必须出现 1-3 条。

## 5. 数值目标

### 5.1 节奏目标

| 战斗 | 目标英雄行动 | 失败/超时警戒 |
|------|--------------|---------------|
| 普通战 | 3-8 | >10 需要检查总 HP、MP 或技能使用率。 |
| 精英战 | 6-14 | >18 需要检查机制是否太肉。 |
| Boss 战 | 10-28 | >35 必须触发破局、狂暴、处决或调数值。 |

### 5.2 行动结构目标

| 英雄类型 | 技能占比 | 普攻占比 | 特殊要求 |
|----------|----------|----------|----------|
| 法术控制 | 55%-85% | <=35% | MP 不能在收割前过早枯竭。 |
| 重甲守卫 | 35%-65% | <=55% | 防御行动必须转化为反击/破防收益。 |
| 高速猎手 | 30%-60% | <=65% | 普攻可以多，但要有收割高潮。 |
| 毒沼消耗 | 45%-75% | <=45% | DoT 必须可见并累计成胜利原因。 |
| 装置代理 | 40%-70% | <=50% | 布置后必须有爆发回报。 |
| 回声支援 | 50%-80% | <=40% | 清除/回声收益必须写进战报。 |

### 5.3 当前优先调参方向

1. 阿斯缇娅：补 MP 续航反馈，不急于直接加强伤害；先让奖励/休息能提示和修正 MP 枯竭。
2. 诺恩：增加防御转输出机制，降低 Boss 超时概率；如果仍拖长，再调 Boss HP 或诺恩反击收益。
3. Boss：增加阶段、破防、狂暴或处决窗口，避免 600 ticks 异常保护成为常见体验。
4. Batch 报告：新增 `tempo_outlier`、`mp_dry_turns`、`defense_loop_turns`、`boss_break_missed`。

## 6. 快照与验收

每个模块必须有固定 seed 或固定输入快照。

| 模块 | 快照宽度 | 验收 |
|------|----------|------|
| 主菜单 | 80 / 100 | 状态、入口、最近 trace 不错位。 |
| 英雄列表 | 80 / 100 | 6 英雄卡片两列/单列都可读。 |
| 英雄详情 | 80 / 100 | 三块结构清楚，无长技能描述撑破。 |
| 路线选择 | 80 / 100 | 3 个节点以内对比清楚。 |
| 奖励选择 | 80 / 100 | 每张卡显示前后变化。 |
| 商店 | 80 / 100 | 四类货架可区分，价格/效果可读。 |
| 休息 | 80 / 100 | 三选一互斥收益清楚。 |
| 战斗主屏 | 80 / 100 / 120 | 左右对战、ACTION、BUILD、ECHO、LOG 都不互相挤压。 |
| Boss 战 | 100 / 120 | Phase/Charge/Break 可见。 |
| 战报 | 80 / 100 | 失败建议和节奏指标可读。 |
| Batch 报告 | 80 / 100 | 胜率、节奏、异常原因都有。 |

## 8. 不通过条件

1. 任何核心界面在 80 列下边框错位。
2. 战斗主屏看不到当前行动目标或裁判结果。
3. Build 推荐撑破屏幕或遮挡敌人信息。
4. Session/token 信息比 HP/MP/ATB 更显眼。
5. Boss 战没有阶段或反制窗口，只靠更厚 HP。
6. 奖励卡没有显示前后变化。
7. 失败战报只说倒下，没有下一局建议。
8. 批量报告只看胜率，不报告拖长和循环原因。

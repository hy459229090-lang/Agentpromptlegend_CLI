# Ouro Agent 战斗演出与 TUI 导演规格

> 版本：v0.1
> 日期：2026-05-16
> 来源：用户反馈、2026-05-16 mock 试玩、策划/美术/研发子 agent 讨论
> 目的：把战斗从“信息拼接出来的 TUI”升级为“有导演感、有局势台词、有数值阈值、有反制窗口、有可实施架构”的 CLI/TUI 战斗体验。

---

## 1. 核心判断

当前战斗已经具备左右对战、角色精灵、弹道、HUD、Build、Session 和日志，但体验仍像“把信息拼起来”。问题不在于字符不够多，而在于缺少一层战斗导演系统：

1. ACTION / IMPACT 没有成为视觉中心。
2. 英雄台词多数是气质句，没有回应当前局势。
3. 模型思考偏调试信息，没有变成“意图、风险、Prompt 命中/偏离”。
4. 数值展示有 HP/MP/ATB，但缺少阈值感和前后变化感。
5. 敌方蓄力、Boss 阶段、破防、错过窗口没有完整三段式反馈。
6. `screens.py` 已经承担页面、资产、布局、文案、战斗导演多重职责，继续硬塞会让后续实现失控。

下一阶段目标：

> 每个 Battle Frame 都要让玩家一眼看懂“谁制造了什么威胁、英雄为什么这样做、本地裁判造成了什么后果、这一步对胜负有什么意义”。

---

## 2. 战斗用户旅程

### 2.1 战前

玩家进入战斗前必须看到：

1. 场景和楼层。
2. 敌方剪影、家族、档次和风险。
3. 当前 Build 阶段和本战建议。
4. 已知图鉴提示。
5. 本战可能出现的反制窗口。

战前目标不是介绍剧情，而是建立预期：

```text
BATTLE START :: EMBER CRYPT F3

Enemy   : [II:k] Black Candle Firekeeper
Threat  : delayed chant, high ATB burst
Build   : [ONLINE] shadow/control
Plan    : keep 18 MP for Hex Seal; break chant before release.
```

### 2.2 每个 Turn

每个 turn 固定使用 9 层信息优先级：

1. 当前威胁：谁行动、谁即将行动、是否有蓄力/破防/低血/处决窗口。
2. 行动标题：`ACTION Hex Seal -> Firekeeper | VALID | interrupt`。
3. 画面表现：左英雄、右敌人、中线效果、受击/格挡/破防姿态。
4. 数值结算：伤害、治疗、护盾、MP/CD、状态、ATB 前后变化。
5. 策略意义：是否命中 Prompt、Build、Codex 或反制窗口。
6. 局势台词：英雄/敌人只说 1 行，必须绑定当前事件。
7. 模型解释：默认压缩为 1-2 行 Intent/Risk，不显示长调试思考。
8. 短日志：最多 4-6 行，补充最近事件。
9. 证据字段：Echo Cost、Ritual Time、trace 等低优先级展示。

### 2.3 战斗结束

战斗结束先给姿态和结论，再给统计。

胜利：

1. 胜利姿态。
2. 最后一击或关键转折。
3. Build / Codex / Prompt 贡献。
4. 行动统计和奖励。

失败：

1. 失败姿态。
2. 直接死亡原因。
3. 错过的资源、目标、Build、Prompt 或反制窗口。
4. 下一局 1-3 条建议。

## 3. 战斗导演层

新增一个概念：`BattleDirection`。它不是规则引擎，也不改结算，只负责把事实组织成玩家可感知的戏剧节拍。

### 3.1 节拍类型

| Beat | 触发 | 展示 |
|------|------|------|
| `threat` | 敌人高 ATB、蓄力、Boss 阶段、低血处决窗口 | Header 或 Action 前提示。 |
| `intent` | 模型准备行动或已选行动 | 1 行意图和 1 行风险。 |
| `windup` | 行动前摇 | 行动者 pose、短台词、效果 lane 起点。 |
| `impact` | 伤害、护盾、状态、ATB 变化 | 数值浮动和目标受击 pose。 |
| `judge` | 本地裁判结算 | `VALID` / `FALLBACK` / `DENIED` 短结果。 |
| `counter` | 打断、破防、格挡、反击 | 横幅：`CHARGE BROKEN` / `BREAK WINDOW USED`。 |
| `climax` | 击杀、险胜、Build 升级、Boss 转阶段 | 独立事件横幅和战报回指。 |
| `aftermath` | 日志和下一威胁 | 更新 HUD，追加短日志。 |

### 3.2 `--no-animation` 规则

`--no-animation` 只取消延迟和微动画，不取消导演节拍。

最低输出必须包含：

1. `SELECT / INTENT`
2. `IMPACT`
3. `JUDGE`

可以在一屏中压缩展示，但不能退化为最终快照。

## 4. 英雄台词规格

英雄台词不是随机气质句，而是局势反馈。每个英雄至少定义 8 类台词，每类至少 3 条。

| 类别 | 触发 |
|------|------|
| `intro` | 战斗开场。 |
| `advantage` | 敌方低血、己方安全、Build 在线。 |
| `low_hp` | HP 低于 30%。 |
| `mp_low` | MP 不足以释放关键技能或低于关键阈值。 |
| `interrupt_success` | 打断、沉默、破防成功。 |
| `build_trigger` | 羁绊触发、Build 阶段提升、拿到关键标签。 |
| `boss_phase` | Boss 进入新阶段或蓄力。 |
| `near_defeat` | 英雄 HP 极低或敌方即将释放致命技能。 |

台词规则：

1. 每次最多 1 行。
2. 必须贴近局势，不能每回合泛用。
3. 不能改变规则含义。
4. 主屏短台词，长剧情留给战前/战后。

示例：

```text
LOW HP     Astia: The candle is guttering. One seal left, if I can pay for it.
MP LOW     Astia: I cannot seal the next chant without more echo.
INTERRUPT  Astia: There. The wick forgets its prayer.
```

## 5. 模型决策表达

主屏不再展示大段模型思考。每次英雄行动展示三元信息：

```text
INTENT  interrupt fastest caster
RISK    spends last 18 MP; no seal next turn
ALIGN   Prompt: Control hit | Build: shadow/control
```

规则：

1. `Intent` 必须是玩家语言，不是 debug。
2. `Risk` 必须说明代价或潜在失误。
3. `Align` 显示 Prompt/Build/Codex 是否支持这次行动。
4. 完整模型原文进入 trace/replay。

## 6. 数值阈值反馈

数值不只显示当前值，还要告诉玩家“是否影响下一次关键行动”。

### 6.1 资源阈值

| 资源 | 阈值反馈 |
|------|----------|
| HP | safe / wounded / critical / lethal risk |
| MP | enough for key skill / below interrupt cost / empty |
| ATB | charging / ready / enemy acts before hero |
| CD | ready / 1 turn / locked |
| Shield | absorbs next hit / partial / broken |

### 6.2 数值 delta

每次行动必须显示关键前后变化：

```text
MP    72 -> 54   enough for Hex Seal: yes
HP    13 -> 2    lethal risk
ATB   Firekeeper 92 -> 48   chant delayed
```

主屏只显示最关键 2-3 条，完整 delta 进 trace/replay。

## 7. 反制窗口规格

反制窗口必须三段式：

1. 预告：敌人即将蓄力、护盾即将打开、Boss 即将转阶段。
2. 窗口：当前 turn 可打断/破防/处决。
3. 结果：成功、错过、失败，并写入战报。

示例：

```text
THREAT  Firekeeper chant 2/3. Release next enemy turn.
WINDOW  Hex Seal or stagger can break the chant now.
RESULT  CHARGE BROKEN | ATB -30 | incoming burst cancelled.
```

错过时：

```text
MISSED WINDOW  Firekeeper released chant after 2 turns unbroken.
REPORT NOTE    No control skill was ready; MP was 0/72.
```

## 8. 美术表现规格

### 8.1 视觉层级

1. Header 场景层。
2. Duel 对战层。
3. Action 聚焦层。
4. Build/Session 辅助层。
5. Log/Evidence 层。

Action 聚焦层必须位于 Build/Session/Log 之前。

### 8.2 效果 Lane

| 类型 | ASCII |
|------|-------|
| 法术 | `--*==>` |
| 打断 | `--x--` |
| 箭矢 | `====>` |
| 毒雾 | `~~~>` |
| 护盾 | `<[#]>` |
| 敌方攻击 | `<== strike` |
| 敌方吟唱 | `<== chant` |

命中点靠近目标侧：

```text
--*== seal ==>   [SLN] -16
```

### 8.3 事件横幅

大事件必须有强反馈：

1. `CHARGE BROKEN`
2. `BREAK WINDOW OPEN`
3. `BUILD ONLINE`
4. `HIGH ROLL`
5. `CODEX REVEALED`
6. `BOSS PHASE II`
7. `EXECUTE`
8. `LAST CANDLE`

## 9. 技术架构规格

后续 TUI 战斗升级必须从直接字符串拼接改为四层架构。

```text
Engine Event
  ↓
BattleFrame Builder
  ↓
BattleScreenModel
  ↓
Layout Blocks
  ↓
Terminal Presenter
```

### 9.1 Engine Event

引擎继续只负责事实，不带美术。

事件示例：

1. `damage_applied`
2. `status_added`
3. `mp_spent`
4. `cooldown_set`
5. `atb_changed`
6. `enemy_charge_changed`
7. `judge_resolved`
8. `battle_end`

### 9.2 BattleFrame

`BattleFrame` 是 TUI 的核心输入。

建议字段：

```python
BattleFrame:
    frame_id
    battle_id
    battle_session_id
    tick
    turn_index
    phase
    actor_id
    target_ids
    action_label
    action_type
    skill_id
    judge_label
    valid
    fallback_reason
    resource_deltas
    actor_pose
    target_pose
    effect_kind
    effect_glyph
    floating_numbers
    threat_summary
    intent
    risk
    alignment
    dialogue_line
    event_banner
    session_usage
    build_summary
    recent_log
```

### 9.3 Render Model

`BattleScreenModel` 不读规则对象，只读 `BattleFrame`。

组件：

1. `HeaderModel`
2. `ActorPanelModel`
3. `EffectLaneModel`
4. `ActionFocusModel`
5. `BuildHudModel`
6. `SessionModel`
7. `LogModel`

### 9.4 Layout Blocks

新增统一布局组件：

1. `Block`
2. `panel`
3. `hstack`
4. `vstack`
5. `fit_text`
6. `wrap_visual`
7. `assert_width`

所有宽度处理必须使用 `visual_width()`，禁止裸 `line[:width]` 作为核心布局手段。

### 9.5 Presenter

CLI 的 `play/run/replay` 不再各自拼 frame。统一由 `tui.presenter` 处理：

1. `model_waiting`
2. `turn_frame`
3. `no_animation`
4. `refresh`
5. `scroll`
6. `replay`

## 10. 80/100/120 列规格

### 10.1 80 列

保留左右关系，压缩次要信息。

```text
EMBER CRYPT F1                              AUTO  seed 7
.. ash candles .. broken arch ..

[CNDL] ASTIA                  -- seal -->       [c] CULTIST
  .^.                         -16 HP SLN          (x)
 /|c|==*                      BREAK              /|!
  / \                                            / \

HP ######## 100/100  MP ####-- 54/72      HP #####--- 34/50
ATB ######  BUFF -                       ATB #####-  DEBUFF SLN(1)

ACTION  Hex Seal -> Cultist | VALID | -16 HP | silence(1)
INTENT  interrupt fastest caster | RISK last 18 MP
BUILD   [ONLINE] shadow/control | NEXT control +1
LOG     Astia spends 18 MP. Chant is interrupted.
```

### 10.2 100 列

默认推荐布局，完整左右面板。

```text
OURO AGENT :: EMBER CRYPT F1                                      AUTO WATCH
.. candles .. broken arch .. ash line ..                          Echo local

+---------------- HERO ----------------+   -- seal -->   +--------------- ENEMY ---------------+
| [CNDL] ASTIA                         |     -16 HP      | [c] HUNGRY CULTIST                  |
|   .^.                                |     [SLN]       |   (x)                               |
|  /|c|==*                             |   BREAK         |   /|!                               |
|   / \        shadow burst            |                 |   / \        staggered              |
| HP [########] 100/100                |                 | HP [#####---] 34/50                 |
| MP [####--] 54/72 ATB [######]       |                 | ATB [#####-] DEBUFF SLN(1)          |
+--------------------------------------+                 +-------------------------------------+

ACTION  Hex Seal -> Hungry Cultist | VALID | -16 HP | silence(1)
INTENT  interrupt fastest caster | RISK spends last 18 MP | ALIGN Control hit
BUILD   [ONLINE] [W:STF] shadow 3/3 control 2/3 | NEXT control affix
ECHO    Battle be_017 | Echo Cost 0 | Ritual Time 12ms | Trace local
LOG     > Astia casts Hex Seal. MP 72 -> 54. Chant broken.
```

### 10.3 120 列

导演版，允许更多队列和威胁信息，但不恢复长模型思考。

## 12. 验收标准

1. 固定 seed 普通战、精英战、Boss 战，每场至少出现一次“威胁预告 -> 行动选择 -> 裁判结果 -> 策略意义”链路。
2. 每个英雄至少有 8 类局势台词，每类至少 3 条。
3. 每次英雄行动主屏显示 Intent、Risk、Align。
4. MP/HP/ATB/CD 至少两类资源能显示前后变化和阈值影响。
5. Boss 战必须展示 Phase/Charge/Break/Enrage；错过窗口写入战报。
6. 大事件必须出现横幅或等价强反馈。
7. `--no-animation` 仍保留 SELECT/IMPACT/JUDGE。
8. 80/100/120 列中文和英文输出均无关键字段溢出。
9. 新架构下战斗屏渲染不再直接从 `TurnRecord` 猜测所有美术含义，而是消费 `BattleFrame` 或兼容转换层。

# Ouro Agent 设计基线与术语表

> 版本：v0.3
> 日期：2026-05-03
> 用途：跨文件一致性的唯一基线。新增玩法术语、ID、档次、节点类型时必须同步更新本文件。

---

## 1. 命名基线

| 项 | 标准 |
|----|------|
| 项目名 | Ouro Agent |
| 副标题 | Prompt Legend |
| 中文描述 | 命令行 AI 肉鸽 |
| 视觉风格 | 严肃暗黑、克制、终端感 |
| MVP 代号 | `mvp_a` |

---

## 2. 核心术语

| 术语 | 定义 |
|------|------|
| 英雄 | 玩家本局配置的唯一战斗角色 |
| 英雄 Prompt | 玩家写入的战斗倾向和策略偏好 |
| Build | 英雄当前的装备、技能、词条、羁绊、Prompt 组合 |
| Build Archetype | Build 的打法类型，如黑烛打断、铁壁反击、裂弦收割 |
| 词条 | 可影响数值、行为、标签或特殊效果的构筑单元 |
| 羁绊 / 回响 | 多个标签满足条件后触发的固定特殊效果 |
| 怪物家族 | 同一怪物机制族群，包含 I/II/III 三档变体 |
| 怪物档次 | 怪物在同一家族中的强度和机制复杂度 |
| 图鉴 | 怪物情报系统，按 family + tier 决定模型能看到多少敌人机制 |
| 读条 / ATB | 单位行动进度条，满后执行行动 |
| 裁判 | 本地规则系统，校验 action 并结算结果 |
| trace | 每场战斗和每次模型行动的可复盘记录 |
| BattleLLMSession | 一场战斗内持续存在的模型会话，复用静态上下文并接收 turn delta |

---

## 3. 固定动作类型

| action type | 中文 | 说明 |
|-------------|------|------|
| `basic_attack` | 普通攻击 | 不消耗 MP，基础行动 |
| `cast_skill` | 使用技能 | 受 MP、冷却、目标规则限制 |
| `use_item` | 使用道具 | 受库存限制 |
| `defend` | 防御 | 降低短期伤害或获得护盾 |
| `observe` | 观察 | 获得战斗内情报或推进图鉴 |
| `change_stance` | 调整姿态 | 改变后续行为倾向或属性 |

任何模块不得新增 action type，除非先更新本文件和模型行动策划案。

---

## 4. 装备和内容档次

| tier | 中文 | 设计规则 |
|------|------|----------|
| `common` | 普通 | 主要提供稳定数值 |
| `heroic` | 英雄 | 数值更高，并带固定触发效果 |
| `legendary` | 传奇 | 数值更高，并给模型有限自由度选择适配效果 |

注意：`heroic` 是系统 ID，展示文案使用“英雄”。

### 4.1 怪物档次

| monster tier | 中文 | 设计规则 |
|--------------|------|----------|
| `trace` | I 碎影 | 普通怪，机制清晰，教学和基础收益 |
| `ritebound` | II 仪式 | 精英/宝箱怪，数值和机制升级 |
| `archive_bound` | III 档案化 | Boss/Nemesis，阶段机制和图鉴突破 |

## 5. 节点类型

| node type | 中文 | 是否战斗 | 主要收益 |
|-----------|------|----------|----------|
| `normal_combat` | 普通怪 | 是 | 金币 + 经验 |
| `elite_combat` | 精英怪 | 是 | 更多经验 + 高品质奖励 |
| `mimic_chest` | 宝箱怪 | 是 | 金币 + 经验 + 装备/Build 选择 |
| `shop` | 商店 | 否 | 购买、替换、调整 Prompt |
| `event` | 事件 | 可选 | 增益、诅咒、交易 |
| `boss` | Boss | 是 | 通关、解锁、大额奖励 |

## 6. Session 名称

| Session | 生命周期 |

## 8. 基础资源与属性

| 字段 | 中文 | 说明 |
|------|------|------|
| `hp` | 生命 | 归零则死亡 |
| `mp` | 法力 | 使用技能消耗 |
| `atb` | 读条 | 满后行动 |
| `speed` | 速度 | 影响读条增长 |
| `attack` | 攻击 | 影响物理或基础伤害 |
| `defense` | 防御 | 降低受到伤害 |
| `power` | 威能 | 影响技能伤害 |

MVP 不引入复杂命中、闪避、暴击，除非后续专门策划。

## 9. 状态效果基线

MVP 可用状态先限制在少量高识别度状态：

| status | 中文 | 类型 | 作用 |
|--------|------|------|------|
| `status_shield` | 护盾 | Buff | 抵消伤害 |
| `status_focus` | 凝神 | Buff | 下一次技能增强 |
| `status_haste` | 急速 | Buff | 提高 ATB 获取 |
| `status_guard` | 守势 | Buff | 防御提高或触发反击 |
| `status_echo_charge` | 回声充能 | Buff | 累积后释放额外效果 |
| `status_stealth` | 潜行 | Buff | 降低受击或增强下次攻击 |
| `status_codex_mark` | 图鉴标记 | Buff | 对已标记目标获得克制 |
| `status_poison` | 中毒 | Debuff | 每次行动前受到伤害 |
| `status_bleed` | 流血 | Debuff | 行动或被攻击时受到伤害 |
| `status_corruption` | 腐化 | Debuff | 暗影/毒相关羁绊计数和易伤 |
| `status_silence` | 沉默 | Debuff | 延迟或限制技能行动 |
| `status_exposed` | 破甲 | Debuff | 防御下降 |
| `status_stagger` | 失衡 | Debuff | ATB 延迟或行动推迟 |
| `status_omen` | 厄兆 | Debuff | 若干回合后触发惩罚 |
| `status_ember` | 灼烬 | Debuff | 行动或受击时触发小伤害 |

## 10. 版本字段基线

| 字段 | 中文 | 用途 |
|------|------|------|
| `schema_version` | Schema 版本 | 内容数据、action、trace 的结构版本 |
| `ruleset_version` | 规则版本 | 战斗规则、结算规则和模式规则版本 |
| `content_version` | 内容版本 | 英雄、技能、装备、敌人、副本数据版本 |
| `run_id` | 单局 ID | 标识一整局肉鸽 |
| `battle_id` | 战斗 ID | 标识一场战斗 |
| `turn_id` | 行动 ID | 标识一次 Model Turn 或敌人行动 |
| `battle_session_id` | 模型战斗会话 ID | 标识一场战斗内持续的 LLM Session |
| `static_context_hash` | 静态上下文 hash | 标识已注入的英雄、Build、技能、图鉴等静态上下文 |
| `delta_context_id` | 回合上下文 ID | 标识一次 turn delta |

G09、G11、G12 必须使用这些字段，不能另造同义字段。

## 11. Provider 基线

| provider | 中文 | 说明 |
|----------|------|------|
| `mock` | 模拟 Provider | 本地试玩和测试，不联网 |
| `openai` | OpenAI | OpenAI 官方 API |
| `anthropic` | Anthropic | Anthropic 官方 Messages API |
| `openai-compatible` | OpenAI 兼容 | 自定义 `base_url` 和模型名 |

Provider 相关字段统一使用 G15 定义，不允许在实现中另造 `vendor`、`backend` 等同义字段。

## 12. 视觉模式基线

| visual mode | 中文 | 说明 |
|-------------|------|------|
| `ascii` | ASCII 安全模式 | 默认模式，兼容 Windows PowerShell 和 CI |
| `unicode` | Unicode 增强模式 | 使用块字符、细线等增强显示 |
| `no_color` | 无颜色模式 | 禁用 ANSI 颜色，便于兼容和测试 |

## 13. 跨文件变更规则

如果任何模块要新增以下内容，必须同步更新本文件：

1. 新 action type。
2. 新 node type。
3. 新 tier。
4. 新基础属性。
5. 新 ID 前缀。
6. 新 Session 类型。
7. 新状态效果。
8. 新 Provider 类型。
9. 新视觉模式。

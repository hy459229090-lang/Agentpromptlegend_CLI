# Ouro Agent CLI 游戏化体验、美术与 Build 深化规格

> 版本：v0.2
> 日期：2026-05-04
> 来源：RicHe 对当前 CLI 战斗交互、美术、Build 爽感、图鉴和 context 成长的反馈
> 目的：把 Ouro Agent 从“命令行系统 Demo”推进到“CLI 风格但真正像游戏”的设计合同。

---

## 1. 核心目标

Ouro Agent 不是接口测试工具，也不是纯文字日志。它应该是一个适配 CLI 的游戏界面：

1. 有清楚的游戏流程和可点击/可输入入口。
2. 有场景、图标、卡片、面板和状态反馈。
3. 有角色立绘、动作、受击、施法、死亡、胜利等资产规格。
4. 有怪物图鉴卡片和未解锁迷雾/占位。
5. 有肉鸽 Build 成型、凑齐、胡牌的快感。
6. 有经验成长和 context 窗口扩张，让玩家持续变强。

---

## 2. CLI 游戏界面原则

CLI 不是只能输出纯文本。MVP+ 的界面分三级：

| 等级 | 名称 | 能力 | 用途 |
|------|------|------|------|
| L0 | ASCII-safe | 纯 ASCII 面板、符号、卡片框 | Windows PowerShell、CI |
| L1 | ANSI/Unicode | 颜色、Unicode 图标、块状血条、局部清屏 | 默认现代终端 |
| L2 | Rich/TUI | 键盘导航、面板布局、卡片列表、轻量动画 | 后续正式可玩版本 |

规则：

1. L0 必须可用，保证兼容。
2. L1 是玩家默认推荐体验。
3. L2 可以后续实现，但文档和架构必须预留。
4. 不允许把 L0 当成最终审美上限；ASCII-safe 是兼容底线，不是美术目标。

## 3. 游戏流程界面地图

```text
MAIN MENU
  ├─ New Run
  │   ├─ Choose Hero
  │   │   ├─ Hero Card
  │   │   ├─ Build Preview
  │   │   └─ Prompt Strategy
  │   ├─ Choose Starting Relic / Weapon
  │   └─ Enter Dungeon
  ├─ Codex
  │   ├─ Monster Cards
  │   ├─ Locked / Fog Cards
  │   └─ Family Progress
  ├─ Archive / Trace Replay
  ├─ Configure Provider
  └─ Quit
```

每个入口都必须有当前状态和返回路径。玩家不能迷失在命令输出里。

## 4. 战斗场景与背景

战斗画面必须有“场景感”，而不是只有单位列表。

### 4.1 场景背景层

| 场景 | ASCII 背景元素 | Unicode 增强 | 情绪 |
|------|----------------|--------------|------|
| Ember Crypt | `| candles | ash | arch |` | 烛光、拱门、灰烬线 | 新手、黑烛 |
| Ash Gate | `[gate] [shield fragments]` | 门框、碎盾、灰线 | 防守、教学 |
| Hollow Archive | `[index] [missing pages]` | 书页、索引、空格块 | 图鉴、遗忘 |
| Mire Vault | `~ mire ~ vials ~` | 水波、毒瓶、雾 | 毒、预兆 |
| Grave Engine | `[gear] [nails] [crank]` | 齿轮、机关线 | 装置、爆破 |

背景必须低密度，不能挡住 HP/MP/ATB。默认只占 Header 或左右边缘。

### 4.2 战斗布局建议

```text
OURO AGENT :: EMBER CRYPT
| ash candles flicker under a broken arch |

 HERO                                  ENEMIES
 [CNDL] ASTIA                          [I:k] Black Candle Acolyte
  .^.  casting stance                   /#\  chanting
 HP [########--] 82/100                HP [#####-----] 32/70
 MP [#####---] 36/72                   ATB [########--] threat: chant

 ACTION
 Astia raises the black candle.
 shadow >>> [I:k]
 Hex Seal: 12 shadow, SLN silence(2)

 LOG
 > Tick 12 Hex Seal interrupts the chant.
```

## 5. 图标与卡片系统

### 5.1 图标类别

| 类别 | ASCII | Unicode | 用途 |
|------|-------|---------|------|
| 生命 | `HP` | `♥` | HP 条 |
| 法力 | `MP` | `✦` | MP 条 |
| 读条 | `ATB` | `⏳` | 行动条 |
| 武器 | `[W]` | `⚔` | 武器卡 |
| 词条 | `[A]` | `◆` | affix 卡 |
| 羁绊 | `[R]` | `◎` | resonance |
| 图鉴 | `[C]` | `⌑` | codex |
| 锁定 | `???` | `▒▒▒` | 未解锁 |
| 迷雾 | `...` | `░░░` | 部分未知 |

### 5.2 卡片规范

所有可选择对象都应卡片化：英雄、武器、词条、奖励、怪物图鉴。

```text
+------------------------------+
| [W] ASH-STEEL BLADE          |
| tier: common                 |
| ATK +3                       |
| tags: blade / ash            |
| build: bleed, counter        |
| next: basic 5 -> 7           |
+------------------------------+
```

## 6. 怪物图鉴卡片与迷雾

图鉴不能只是文字列表，必须像卡片收藏和战术档案。

### 6.1 未解锁卡片

```text
+------------------------------+
| [??] UNKNOWN FAMILY          |
| tier: ?                      |
| silhouette: ░░░░░            |
| known: first seen in Ash Gate|
| unlock: encounter once       |
+------------------------------+
```

### 6.2 部分解锁卡片

```text
+------------------------------+
| [I:k] BLACK CANDLE ACOLYTE   |
| Codex: observed              |
| HP: 50-70     threat: chant  |
| Known                         |
| - Uses delayed shadow chant. |
| Fog                           |
| - ░░░ weakness hidden ░░░    |
| - ░░░ drop table hidden ░░░  |
+------------------------------+
```

### 6.3 掌握卡片

```text
+------------------------------+
| [II:k] BLACK CANDLE FIREKEEPER|
| Codex: mastered              |
| Family: Black Candle         |
| Weak: interrupt / silence    |
| Resist: shadow 10%           |
| Drop: candle, control affix  |
| Build hint: Control works.   |
+------------------------------+
```

规则：

1. 未解锁信息必须用迷雾/占位，而不是不显示。
2. 卡片要展示进度，让玩家想补全图鉴。
3. 图鉴解锁必须影响 Prompt/context 注入和战斗建议。

## 7. 角色美术资产规格

一个角色不能只有头像。每个英雄至少需要以下资产状态：

| 资产 | 用途 | MVP 形态 |
|------|------|----------|
| 立绘/Portrait | 英雄选择、详情、结算 | 8-12 行 ASCII/Unicode |
| 战斗 Idle | 战斗主屏常态 | 1-3 行短姿态 |
| 施法/Cast | 技能行动帧 | 1-2 行动作 |
| 攻击/Attack | 普攻或武器动作 | 1-2 行动作 |
| 受击/Hit | 承伤反馈 | 1 行姿态变化 |
| 防御/Guard | defend/护盾 | 1 行姿态变化 |
| 低血/Low HP | HP 低于 30% | 1 行状态 |
| 胜利/Victory | 战斗结算 | 1 行姿态 |
| 死亡/Defeat | 失败结算 | 1 行姿态 |

示例：

```text
ASTIA [CNDL]
idle :  .^.   candle low
cast :  .^.   candle raised  ✦
hit  :  .^.   flame bends back
low  :  .^.   candle guttering
win  :  .^.   black flame steady
dead :  ._.   candle out
```

## 8. 动作设计

每个英雄至少定义动作包：

| 动作类型 | 数量 | 示例 |
|----------|------|------|
| 普攻 | 2 | weapon strike / cautious hit |
| 技能 | 每技能 2 | cast start / impact |
| 防御 | 1 | brace / shield / fade |
| 受击 | 2 | light hit / heavy hit |
| 状态触发 | 每核心状态 1 | poison tick / shield break |
| 胡牌/羁绊触发 | 每 Build 1 | resonance active |

怪物也要有动作包：

| 动作类型 | 数量 |
|----------|------|
| idle | 1 |
| attack | 2 |
| cast/charge | 1 |
| release | 1 |
| hit | 1 |
| death | 1 |
| codex reveal | 1 |

## 9. Build 胡牌体验

肉鸽的关键不是“装备加数值”，而是玩家能感到快要成型、已经成型、爆发成型。

### 9.1 Build 成型阶段

| 阶段 | 条件 | UI 反馈 | 战斗反馈 |
|------|------|---------|----------|
| Seed | 拿到 1 个核心标签 | `Build seed found` | 技能提示出现 |
| Pair | 核心标签达到 2 | `Pair online` | 小触发日志 |
| Online | 触发 1 个羁绊 | `RESONANCE ONLINE` | 动作帧强调 |
| High Roll | 核心装备 + 2 词条 + 羁绊 | `BUILD HIGH ROLL` | 战斗背景/动作加强 |
| Locked In | Build 达到 2 个羁绊或关键传奇 | `BUILD LOCKED` | 结算卡片展示 |

### 9.2 胡牌反馈样例

```text
BUILD EVENT :: RESONANCE ONLINE

[R] Corruption School
shadow(3) + control(2)

Effect
Corrupted enemies take +4 shadow damage.

Astia's candle burns black.
```

### 9.3 组合展示

Build 面板必须显示“差几张胡”：

```text
BUILD :: BLACK CANDLE INTERRUPT

Core tags
shadow  [###] 3/3  online
control [##-] 2/3  need 1
risk    [#--] 1/2  optional

Active
[R] Corruption School

Near
[ ] Candle Tribunal needs control +1

Best next picks
- Hexed Wick affix       control +1
- Black Sun Codex        shadow +1, codex +1
```

## 10. 经验与 Context 窗口成长

经验不应只加属性。Ouro Agent 的成长核心是“玩家能给 Agent 更多上下文和更好的策略空间”。

### 10.1 Run Level

| Level | XP | 解锁 | 说明 |
|-------|----|------|------|
| 1 | 0 | Prompt style 1、Codex slot 1、Context 低 | 开局 |
| 2 | 20 | Strategy slot +1 | 可保留一条战术原则 |
| 3 | 45 | Codex slot +1 | 可注入更多怪物信息 |
| 4 | 75 | Context window + small | rolling summary 更长 |
| 5 | 110 | Prompt edit token +1 | 可扩写英雄 Prompt |
| 6 | 150 | Build hint slot +1 | 系统给更多胡牌建议 |

### 10.2 Context 资源展示

不要直接把 context 做成抽象 token。UI 用槽位表达：

```text
CONTEXT WINDOW
Battle Echo : be_017
Static      : hero + build + rules
Strategy    : 2/3 slots
Codex       : 1/2 slots
Memory      : 340/500 echo

Upgrade next:
Level 3 -> Codex slot +1
```

### 10.3 经验选择

战后升级时玩家可以选择 context 成长方向：

```text
LEVEL UP :: Agent Context

[1] Strategy Slot +1     keep one more combat principle
[2] Codex Slot +1        inject one more monster card
[3] Memory Echo +120     longer rolling summary

Choose upgrade:
```

## 11. 剧情和副本节奏

剧情服务玩法，不做长小说。每个副本需要三层叙事：

| 层级 | 内容 | 展示位置 |
|------|------|----------|
| 场景句 | 1 行背景 | battle_intro / route |
| 节点事件 | 1-3 行选择说明 | route/shop/event |
| 图鉴碎片 | 解锁后短句 | codex card |

新手副本 `Ember Crypt` 示例：

```text
The archive opens under a field of dead candles.
Every chant you interrupt becomes a line in the Codex.
```

Boss 前：

```text
The Black Candle High Priest has already read your last three turns.
```

## 13. 验收红线

1. 不允许把“CLI 风格”理解为“纯文本无 UI”。
2. 不允许角色只有一张头像，没有动作和状态。
3. 不允许图鉴只是文字列表，没有卡片和未解锁占位。
4. 不允许 Build 只加数值，没有成型阶段和胡牌反馈。
5. 不允许经验只加属性，必须影响 Prompt/context/图鉴/策略空间。

---

## 14. 图形化战斗补充

本规格 v0.2 追加硬要求：`CLI 风格` 不等于 `文字日志`，战斗主屏必须按照 `art/08_战斗界面图形与动作分镜_20260504.md` 实现。

强制规则：

1. 默认战斗主屏必须是左英雄、右怪物的对战站位。
2. 英雄和怪物必须有 4-6 行战斗精灵，不允许只显示短标识。
3. 技能、普攻、格挡、打断、治疗、毒雾必须经过中央效果层表现。
4. 武器必须有图标和轮廓，例如 `[W:STF] c==*`、`[W:XBW] ==>`。
5. Build 必须有徽章阶段，例如 `[SEED]`、`[PAIR]`、`[ONLINE]`、`[HIGH]`、`[LOCK]`。
6. 下方战斗日志只能解释画面，不允许替代画面。
7. `--no-animation` 只关闭等待和微动画，不能关闭 turn frame。
6. 不允许战斗背景、图标、动作全部推迟到“以后再说”；至少要有 L0/L1 设计合同。

# TUI 图形化 Canvas 美术研发规格

> 日期：2026-05-16  
> 状态：P0 实施规格  
> 来源：用户反馈、研发/美术/策划三方复盘  
> 目标：把 Ouro Agent 的 TUI 从字符拼接升级为终端低分辨率图形画布。

---

## 1. 结论

当前 `21_像素风TUI美术研发边界与需求规格_20260516.md` 的 pixel panel 可保留为 ASCII fallback，但它不能作为最终美术目标。

新的方向是：

> 暗黑终端低像素图形剧场。ASCII 是兼容底线，Unicode block / ANSI 色层才是推荐观感目标。角色、怪物、武器、弹道和状态条都应作为低分辨率图形资产绘制，而不是继续在 `screens.py` 中拼接标点。

---

## 2. 技术边界

| 层级 | 用途 | 字符/能力 | 优先级 |
|------|------|-----------|--------|
| ASCII fallback | CI、PowerShell、日志、no-color | `# . : = - / \ | []` | P0 必须 |
| Unicode block canvas | 默认推荐观感 | `█ ▓ ▒ ░ ▀ ▄ ▌ ▐` | P0 |
| Unicode fine pixel | 精灵、弹道、破损、雾面 | `▖ ▗ ▘ ▙ ▚ ▞ ▟` | P1 |
| ANSI theme | HP/MP/ATB、危险、反制、高潮 | 16/256/truecolor，可关闭 | P1 |
| Braille texture | 毒雾、星尘、档案噪声 | Braille 点阵 | P2，可选 |
| Image protocol | 展示型 banner/立绘 | kitty/iTerm2/sixel | P2 实验，不作为 MVP 依赖 |

约束：

1. 默认输出必须 ASCII-safe。
2. Unicode/color 只能增强观感，不能承载唯一语义。
3. 核心画布 glyph 必须是单宽字符。
4. 中文只进入文本层，不进入像素画布层。
5. `--no-animation` 可以去掉延迟，但不能去掉 turn frame、动作节拍和战斗日志。
6. TUI 不修改战斗规则，所有伤害、胜负、掉落仍由本地引擎决定。

---

## 3. 用户旅程目标

玩家运行 `ouro play --mock` 时，应经历以下感受：

1. 第一眼看到左英雄、右怪物、中间效果 lane，而不是报告页。
2. 每个 turn 都能看见 SELECT、IMPACT、JUDGE 三个节拍。
3. 英雄像一个正在执行策略的 Agent，有局势台词和意图/风险/契合提示。
4. 怪物不是血条目标，而是有 idle、attack/cast、hit、break、death 的剪影变化。
5. HP/MP/ATB 不是字段堆叠，而是图形条 + delta + 阈值提示。
6. 武器与 Build 不是装饰字段，而是解释“为什么英雄会这样打”的图形卡。

## 4. P0 需求

| ID | 需求 | 系统行为 | 验收 |
|----|------|----------|------|
| REQ-TUICANVAS-001 | 建立 Surface/Canvas 渲染层 | 新增二维 cell 画布，支持 text、bar、box、sprite、compose、render | 单元测试覆盖固定宽度、sprite 绘制、ASCII fallback |
| REQ-TUICANVAS-002 | 建立 glyph mode | 提供 `ascii` 与 `unicode` 两套单宽 glyph | 所有 P0 glyph `visual_width == 1` |

| REQ-TUICANVAS-005 | 保留 ASCII fallback | 无 `--unicode` 时保持可读、可测、可管道输出 | 现有测试继续通过 |

## 5. 美术规格

### 5.1 人物

P0 每个英雄至少有：

1. ASCII fallback sprite。
2. Unicode block sprite。
3. idle / attack / skill / defend / hit / low / victory / defeat 的等价姿态。
4. 职业锚点：
   - Astia：兜帽、黑烛、火点。
   - Norn：宽盾、重心低。
   - Vela：前倾、弩箭横向。
   - Mirel：瓶形、雾块。
   - Korr：齿轮、背箱。
   - Sera：断铃、声波弧。

### 5.2 怪物

P0 每个 MVP 怪物家族至少有：

1. idle / attack / skill / hit / break / low / death。
2. 家族剪影语法：
   - Hungry Cultist：瘦长、缺口、钩刃。
   - Black Candle：烛芯、黑火、仪式环。
3. 蓄力、破防、死亡必须改变轮廓，而不是只改文字。

### 5.3 战斗画面

P0 战斗主屏必须：

1. 左英雄、右怪物、中间效果 lane。
2. 中间 lane 使用块面弹道，而不是纯文本箭头。
3. 行动结果靠近目标侧显示 `-HP`、`BREAK`、`SLN`、`MISS` 等短标签。
4. ACTION 信息高于 Build、Echo、Log。
5. 反制窗口、错失窗口、高潮击杀有独立视觉 tone。

### 5.4 武器图鉴

P0 武器仍保留 `[W:*]` 产品识别码，同时补充：

1. icon：短标识。
2. silhouette：一行轮廓。
3. card art：3-5 行块面资产。
4. Build Before -> After 与 AI 行为影响说明。

## 6. 研发实施顺序

1. 新增 `src/ouro_agent/tui/canvas.py`：`Cell`、`Surface`、绘制与 render。
2. 新增 `src/ouro_agent/tui/glyphs.py`：ASCII / Unicode glyph set。
3. 新增 `src/ouro_agent/tui/theme.py`：语义 tone 与未来 ANSI 色层。
4. 新增 `src/ouro_agent/art/block_sprites.py`：英雄、怪物、弹道、武器低像素资产。
5. `render_battle_screen()` 在 `unicode_mode=True` 时使用 Canvas battle stage。
6. 增加 80/100/120、英文/中文、ASCII/Unicode 的宽度测试。
7. 固定 seed mock demo 保存命令输出或人工试玩记录。

---

## 7. 不做

1. 不在 Slice 0/A 直接上 Textual 重写默认战斗。
2. 不依赖 Nerd Font、emoji 或外部字体。
3. 不把 kitty/iTerm2/sixel 图片协议作为核心体验。
4. 不让颜色成为唯一语义。
5. 不通过增加长文案解释来掩盖战斗画面不足。

---

## 8. 完成口径

P0 完成后，固定 seed demo 应满足：

1. 无 `--unicode`：仍然 ASCII-safe、可读、可测试。
2. 带 `--unicode`：战斗主舞台明显变为低像素图形画布，可见块面人物、怪物、弹道和 HUD。
3. `--no-animation`：仍保留逐 turn frame。
4. 每个完成 REQ 都有测试、命令输出、trace、截图/log 或人工试玩记录。

## 3. 发现的问题与修正

| 问题 | 影响 | 处理 |
|------|------|------|
| 原先第一轮只强调战斗闭环 | 容易做成本地脚本，不像可发布产品 | 已新增 Slice 0：安装、CLI、Provider、README、ASCII-safe |

## 4. 仍需 RicHe 决策的问题

| 问题 | 建议 |

## 5. 实现前最终 Gate

进入 coding 前，应该只批准：

1. Slice 0：可安装 CLI 骨架、README、Provider 配置、ASCII-safe 主屏骨架。
2. Slice A：读条战斗、mock model、action schema、裁判、trace。

暂不批准：

1. 完整商店。
2. 完整副本。
3. 真实模型完整调用。
4. 排行榜。
5. 玩家对战。
6. 大量内容填充。

---

## 6. 结论

文档逻辑现在基本统一。后续风险不在“缺文档”，而在实现阶段跳过需求矩阵、直接做大功能。因此 Cursor / Claude Code 指引必须要求：

1. 先读 `06_需求追踪矩阵_20260503.md`。
2. 只实现 ready 状态的需求。
3. 每个完成需求补证据。
4. 修改玩法术语时同步设计基线。
